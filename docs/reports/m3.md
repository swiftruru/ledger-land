## 8. 新發現

1. **本機 Lighthouse 的 LCP 以一次往返為一級跳動**：wrangler dev 是 HTTP/1.1，模擬時每條連線分到「頻寬除以同時進行的請求數」，第一波的位元組或請求多到跨級就多約 150ms；瀏覽器自己抓的 favicon、manifest 與安裝圖示也算在 LCP 之前。改成 favicon 寫進 HTML、manifest 連結第一次繪製後才插入、作答頁第一波從 10 個 chunk 變 5 個（06 第 8.2 節「M3 收尾 QA 的實測教訓」）。要看的是總量有沒有跨級，單看一個檔案常常看不出差別。
2. **ResizeObserver 的無害通知會讓錯誤紀錄在 LCP 前開資料庫**：地圖頁偶爾在 window 上出現「ResizeObserver loop …」，錯誤紀錄因此多載約 16 KB；觸發點改到下一個影格，錯誤紀錄也等第一次繪製後才寫入、不記這個通知（06 第 9.2 節）。
3. **rolldown 的群組會連依賴一起抓**：第一次繪製就要、又是 runtime 依賴的小模組要由先宣告的群組拿走；切詞這類共用小模組放錯群組會讓設定頁載入整個名詞卡 chunk（06 第 8.2 節、07 第 3.5 節）。
4. **Chromium 在 `white-space: nowrap` 的 span 裡不套用 `text-spacing-trim`**：開括號與開引號要放在 span 外面；`.ll-nowrap` 緊接的標點放不下時會落到下一行行首。
5. **`content-visibility` 會裁掉超出區段的章節牌**：文字放大 200% 時章名排成五到七行，章節牌比區段高；改成依量到的卡片高度排版。
6. **PingFang TC 的 ASCII 連字號寬 0.6em**：比數字還寬，關卡代號看起來像破折號；字型堆疊改成拉丁系統字在前。
7. **`i18n:check` 在還沒 commit 的 catalog 上一定失敗**：它和 HEAD 比對；等效的驗證是 extract 前後工作樹雜湊不變加上 `lingui-missing.mjs`。
8. **E2E 不能寫死內容的文字**：降低原創性重疊時名詞定義改寫，寫死舊定義的 7 個 E2E 一直失敗；E2E 的期待值一律從快照讀（`apps/web/e2e/glossary-data.ts`）。

## 9. 已知限制

- **預算的餘裕很小**：`/en/` 首次載入 JS 只剩約 0.5 KB、入口 CSS 0.3 KB、全部 CSS 0.3 KB、地圖 chunk 0.5 KB。作答頁三個網址的入口 CSS 再多約 1 KB 就會回到約 2580ms。新增字串或樣式前先量；M4a 開工時第一件事拆 catalog（14 第 5.2 節）。
- **五種中文切詞工具還沒合併**：規則相同但粒度不同，合併會改變已經看圖驗收過的換行，要重拍整套圖（07 第 3.5 節）。
- **夜空的沙地**維持在地景 1.45 倍的上限內，審查建議的更亮版本待我看圖決定（14 第 5.2 節）。
- **fixture 建置的 E2E 不在 CI**：按鈕狀態板與橫幅矩陣只在本機補跑（256 個通過）；CI 的 e2e 用正式建置。
- **desktop-firefox 的 E2E 只在 CI 跑**，本機沒有跑；這次的 E2E 結果是 Chromium、WebKit 與 reduced-motion 三個專案。
- **安裝建議的顯示細則**是簡易版（第 6 節第 11 點）。
- **實驗室步驟的路由還沒有**：章末紙籤與章節頁的實驗室連結都不顯示，M4a 起才出現。
- **sitemap 沒有實作（既有缺口）**：02 第 1.3 節、05 第 9.3 節規定建置時產生 `sitemap.xml` 與 `robots.txt`，從 M0b 起一直沒有做；目前只有用戶端寫入的 canonical、hreflang 與 `noindex`。不影響網站本身，只影響搜尋收錄；排程待我決定（14 第 5.2 節，我建議在 M4a 開工時補上）。
- **還沒 commit 與部署**：正式網址仍是 M2 的版本；commit 之後 `i18n:check` 才會通過，CI 也才會跑 Firefox 與 main 的 5 次 Lighthouse。
