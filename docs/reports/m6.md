## 1. 開工前的決定

10 第 13 節列了兩件開工前要處理的事，加上實作時碰到的兩件，都寫在 [14 待確認](../plan/14-open-questions.md) 第 5.2 節：

1. **xlsx 函式庫：不加，自己寫**。查證（2026-11-08）：SheetJS CE 0.20.3 寫 .xlsx 時不會寫入資料驗證下拉清單（寫入器原始碼只有 `dataValidations` 的註解佔位，「Data Validations」列在 Pro 的功能清單）；read-excel-file 只讀；write-excel-file 的核心沒有資料驗證，要靠 1.0.2 的第三方插件；exceljs 停在 2023 年的 4.4.0。xlsx 是 zip 加 XML，repo 已經有自己的 zip 讀取器（講義 pptx 用），補一個對稱的寫入器與幾個 XML 範本就夠；沒有 vendored tarball 要人工追版、沒有新的授權聲明。CSV 自己解 RFC 4180，Big5 用 Node 內建的 `TextDecoder('big5')`。
2. **瀏覽器匯入頁先不做**。老師 2026-11-06 的信還沒回（T34 第 (3) 問）；解析、組裝、驗證與差異摘要都寫成不碰檔案系統的純函式，之後搬到匯入頁不用改。（2026-11-08 晚上補記：老師沒有正面回答，我決定匯入頁等 M7 後台一起做；老師的題用他在 iClass 出題的 ee-class 第 4 版 CSV 格式匯進講義題庫，先接進本機指令 `pnpm handout:import`，PR 132；見第 13 節）
3. **表格沒有的欄位原樣保留**：匯入是「以表格的欄位覆蓋 JSON 的對應欄位」，不是整筆取代。`ratioTable`、`distractorExprs`、`display`、名詞的 `labRefs`、`unlock` 不在表格上。
4. **範本現場產生、`.xlsx` 不 commit**：09 原本「手工做好一份範本檔並 commit」的備案不成立，因為 `.xlsx` 本來就是 hygiene 禁止追蹤的副檔名。

## 8. 新發現

- `TextDecoder('big5', { fatal: true })` 對 `FF FE 41` 這種位元組不丟錯、解出空字串（ICU 的 Big5 和 WHATWG 的行為不完全一樣），所以 UTF-16 的 BOM 要自己先擋。
- Python 的 `big5` 編碼器能把「③」存進去，Node 的解碼器解不回來；Big5 之間也有方言差異，來回測試一定要用真實資料。
- Zod 4 對缺少的 enum 欄位回報的是 `Invalid option: expected one of …`，不是 `Required`；中文化時把它翻成「值不在允許的清單裡（…）」，缺值與填錯值看起來一樣，但欄位就在那一格，夠用。
- `check:tw` 是掃檔案的獨立腳本，`content:check` 不含它；第一版匯入沒有檢查中國用語（故意弄壞的工作簿裡那一句沒被抓到），之後把對照表抽成 `tools/lib/tw-style.mjs` 共用。
- 測試裡自己打的 ID 要避開 Crockford Base32 沒有的 i、l、o、u（`q_s1ngl3aa` 被 Zod 擋在基準裡，讓一整個案例看起來「沒有錯誤」）。

## 9. 已知限制

- 一次只能有一個人編輯：兩人各自編不同副本時，第二個匯入的人會看到衝突（`baseRev` 不等於目前的 rev）；這是 08 第 9 節寫明的取捨，M7 的後台才處理多人。
- 選項與分類項目要和題目列一起匯入（`questionId` 不在題目表裡就是錯誤）；只改選項也請把題目列一起匯出。
- 有選項列的題目選項整組以表格為準；刪掉的選項 ID 由 lock 的 `id.optionReused` 擋住再用。
- Big5 的 CSV 放不下的字會變形（第 3 節第 3 條）。
- 沒有自動更新 lock、沒有自動開 PR（流程照 08 第 6.3 節）。
