# 05 多語系

這份文件規劃 LedgerLand 的中英雙語架構：語系清單集中放在 `packages/i18n`，介面字串交給 Lingui 6，題目與名詞等內容用 `{ "zh-TW": ..., "en": ... }` 欄位存放，zh-TW 必填。它也規定缺翻譯時怎麼退回與標示、怎麼產生翻譯報表、金額與日期怎麼格式化才能讓同一題在兩種語言的數值完全一致，以及英文介面的報表怎麼呈現教材裡 IFRS 沒有的列。網址策略已決定（D5，2026-10-20）：中文在根路徑、英文在 `/en/`，先不預先產生 HTML；英文採英式拼字與 en-GB 格式（D11），第 7 節保留三個方案的比較紀錄並寫出決定後的做法。

## 確定要做

- **語系登錄檔**：`packages/i18n` 記錄每個語系的代號、顯示名稱、`html lang`、hreflang、數字與日期格式、退回語系、狀態（complete 或 beta）。zh-TW 與 en 從 M0b 起都是 complete；beta 只給日後新增的第三種語言使用。web、content-schema、tools 都從這裡讀，不各寫一份。新增語言只要加一筆設定並補翻譯。
- **介面字串用 Lingui 6**：已決定（2026-10-20）：catalog 分兩份，元件裡的文字（例如 `quiz.submit`、多正解題提示、選項狀態字串）放在 `packages/web-ui/src/locales/{locale}/messages.po`，頁面與殼層的文字放在 `apps/web/src/locales/{locale}/messages.po`，兩者在載入時合併，後台同樣合併 `web-ui` 的 catalog（第 3.1 節）。用 ICU 處理英文複數。CI 先跑 `lingui extract`，再跑 `lingui check missing --mode catalog`，complete 語系缺字就讓 CI 失敗。`lingui compile` 的 `--strict` 不是預設，CI 不依賴它判斷缺漏。
- **內容欄位**：題目、選項、解說、名詞卡、交易卡、實驗室說明都用 LocalizedText，zh-TW 必填；內容只有在中英兩種語言都齊全時才能設為已發布（published），草稿可以只有中文。
- **缺翻譯分兩種處理**：介面字串在 zh-TW 與 en 缺翻譯會讓 CI 失敗；只有日後新增、狀態為 beta 的第三種語言，才會在執行期退回 zh-TW，並在語言切換處標「Beta」、第一次切換時說明一次。內容欄位由 ContentSource 回傳「文字、語系、是否為退回」（`ResolvedText`，見第 4.3 節），元件逐元素標示「尚未翻譯」並設定 `lang="zh-TW"`。
- **翻譯報表**：`content:i18n-report` 列出所有缺漏、佔位符不一致與寫死的數字，只對已發布的內容強制。
- **已決定（D5，2026-10-20）：網址採 C 案，中文在根路徑、英文在 `/en/`**。中文關卡是 `/level/lv_k7m2q9xd/`，英文是 `/en/level/lv_k7m2q9xd/`。先不預先產生 HTML：框架採 React Router 8 data mode 加 vite-plugin-pwa，所有頁面共用一份殼層 `index.html`；Cloudflare Workers 的 SPA fallback 對深層連結回傳殼層並給 200（不得回傳語言選擇頁，本案沒有語言選擇頁）；V08 暫不需要。作答狀態放在路由外的 store，切換語言時保留。日後若要加強搜尋收錄，再評估預先產生 HTML（第 7 節）。
- **語言切換**：兩種語言時是切換開關，三種以上自動改成選單；語言由網址決定（`/en/` 開頭是英文，其餘是中文），只有根路徑 `/` 依已存偏好轉到 `/en/`；不跳出語言選擇，也不依瀏覽器語言自動轉址，網址的語言和瀏覽器語言不同時只顯示一次可關閉的切換提示；只記住使用者主動選的語言；切換時以 replace 換到另一種語言的同一頁，作答中切換要保留題目、已選選項、計時與捲動位置（第 8 節）。
- **`html lang` 跟著網址的語言**：殼層寫 `lang="zh-TW"`，boot 腳本在第一次繪製前依路徑改成正確值，切換語言時同步更新；退回的內容與另一種語言的術語在元素上設定自己的 `lang`。hreflang 以建置時產生的 `sitemap.xml` 為主（中英網址互列，x-default 指向中文），用戶端在 head 寫入的 canonical 與 hreflang 只當輔助（第 9 節）。
- **格式化**：內容用佔位符 `{{money:x}}`、`{{percent:x}}`、`{{number:x}}`、`{{date:d}}`、`{{term:tm_id}}`、`{{term:tm_id|plain}}`、`{{option:o_id}}`，x 可以是 `vars.<name>`（題目自帶的數字）、`<eventId>.<參數或推導值>`（例如 `e1.price`）或 `expected.<targetId>.<欄位>`（核心算出的答案），也可以是數字字面值；交易範本的 `summary` 與 `explanation` 另可用 `param.<name>`、`derived.<name>`，核心 `effects` 的片語樣板另可用 `amount`，驗證器依作用範圍檢查（第 10.1、10.5 節）；變動值另有 `|sign` 選項（例如 `{{money:x|sign}}`，正數帶「+」）；另有 04 定義語意、08 提議的 `{{ratio:id@version}}` 與逃生口 `{{raw:...}}`，全部共用第 10.1 節的同一套文法，本文件是文法的依據；Intl 統一設定（TWD 不顯示小數、`signDisplay: 'negative'`、格式化前把 -0 改成 0；唯一例外是 `|sign` 的變動值，改用 `signDisplay: 'exceptZero'`，見第 10.3 節）；報表與輸入框一律顯示完整數字加千分位；「萬元 / million」只在兩種語言都能精確表示時允許。
- **驗證**：用 `formatToParts` 渲染兩種語言再解析回原值比對；可翻譯文字裡不得寫死金額或百分比；兩種語言引用的佔位符集合必須相同。
- **作答輸入正規化**：NFKC、移除全形與半形逗號、接受三種負號，並提供「±」按鈕與指標題的「N/A」按鈕。
- **已決定（D11，2026-10-20）：英文介面的報表沿用教材版面**：列、順序與數值都和中文介面相同，英文列名採 IFRS 英文；IFRS 沒有或禁止的列加上非 IFRS 項目標記，中英兩種介面都加（中文「非 IFRS 項目」、英文「Not an IFRS line item」，字串放在本文件的 Lingui catalog，第 12.1 節），點開名詞卡看 IFRS 的處理方式；英文使用者可以隨時切到 IFRS 對照（D10(f)，M4b，不計分，第 12.3 節）。
- **已決定（D11，2026-10-20）：英文拼字用英式**（與 IFRS 原文一致，例如 amortisation、recognised、organisation），美式拼法列為搜尋別名（Term 的 `enUsVariant`）；`intlLocale` 是 `en-GB`、`ogLocale` 是 `en_GB`，日期格式跟著英式（例如 3 November 2026）。英文介面字串與英文內容用同一份英式拼字的 lint 字表檢查。
- **已決定（D9，2026-10-20）：Tab 與模組名稱**：Tab 用短名（首頁、闖關、實驗室、圖鑑、我的；Home、Quest、Lab、Terms、Me），頁面標題與關於頁用模組全名（闖關區／Quest、報表實驗室／Statement Lab、名詞圖鑑／Glossary），全部寫進 Lingui catalog，Tab 標籤的訊息加 `comment` 註明字數上限。殼層裡的靜態 Tab bar（D8）用同一組名稱，英文網址由殼層在地化腳本在第一次繪製前換成英文（第 9.1 節）。
- **已決定（D12，2026-10-20）：多正解題 `multi_choice` 的兩種固定提示是介面字串**：`any_correct` 顯示「這題有不只一個合理答案，選出任一個即可。」（英文 "This question has more than one reasonable answer. Choose any one of them."），`all_correct` 顯示「選出所有正確答案（可複選）。」（英文 "Select all the correct answers. You can choose more than one."），放在選項群組的 `<legend>` 中，中英兩種語言都由 Lingui 管理，作者不能在內容裡改寫；這兩組字串以本文件的 catalog 為準，其他文件逐字引用。作答的共用按鈕是「確認答案」（"Check answer"），單選題與兩種判分方式的多正解題都按它之後才判分（第 3.6 節）。
- **雙語名詞卡與術語表**：名詞卡同時顯示中英術語（可在設定中關閉），內文用 `{{term:tm_id}}` 帶出術語，確保兩個模組與兩種語言的用詞一致；術語來源是 [12 術語表](12-glossary.md)。已決定（D13，2026-10-20）：W01 到 W15 全部採用，多數仍以教材名稱為主要顯示，只修正筆誤與異寫（例如 W03 統一用「應付帳款」、W08 顯示「資產總計」），教材原字一律保留為可搜尋的別名；「短期放貨」不在 W 系列內，仍等【待確認 T09】。

本文件沒有需評估的項目。原本的三項都已在 2026-10-20 決定，以下保留精簡的決定紀錄（編號不變，方便其他文件引用），要做的事已寫進「確定要做」與內文。

### 一、網址策略：已決定
- **已決定（D5，2026-10-20）**：C，中文在根路徑、英文在 `/en/`。因為主機採 Cloudflare Workers（D4），深層連結可以直接回到網站殼層，所以先不預先產生 HTML，框架採 React Router 8 data mode 加 vite-plugin-pwa（原本 A 案的技術路線），V08 暫不需要；作答狀態放在路由外的 store，切換語言時保留。日後若要加強搜尋收錄，再評估預先產生 HTML。做法見第 7.4 節。

### 三、模組與 Tab 的正式中英名稱：已決定
- **已決定（D9，2026-10-20）**：Tab 用短名（首頁、闖關、實驗室、圖鑑、我的；Home、Quest、Lab、Terms、Me）；頁面標題與關於頁用模組全名：闖關區／Quest、報表實驗室／Statement Lab、名詞圖鑑／Glossary。故事公司取原創名稱（情境與金額照老師的），由規劃者在 M4 前提案、你確認；M8 前查詢「LedgerLand」與「會計樂園」的商標。名稱寫進 Lingui catalog 與安裝教學截圖；Lingui 訊息加 `comment` 註明字數上限（Tab 標籤中文 2 到 3 字、英文 6 個字母以內），與 [02 網站架構](02-site-architecture.md) 第 2.1 節相同。
- **未採用的選項**：中英都只用短名（英文短名比較抽象，第一次看到的人不一定懂）；英文音譯或保留中文名（英文使用者讀不懂，也不利於螢幕閱讀器朗讀）。

## 2. 語系登錄檔（`packages/i18n`）

### 2.1 型別

已決定（2026-10-20）：套件目錄改名為 `packages/i18n`（原名 `i18n-config`），因為它除了語系登錄檔，也放格式化函式（第 10 節）與作答輸入正規化（第 11 節），不只是設定；npm 套件名稱是 `@ledgerland/i18n`，M0b 建立。Lingui 的介面字串檔不放在這個套件（第 3.1 節）。目錄結構與依賴方向以 [09 技術選擇](09-tech-stack.md) 為準。

```ts
// packages/i18n/src/types.ts
export type LocaleStatus = 'complete' | 'beta';
export type UnitKey = 'day' | 'times';

export interface UnitPattern {
  /** 依 Intl.PluralRules 的分類填寫；中文只有 other */
  one?: string;
  other: string;
}

export interface LocaleDef {
  /** BCP 47 代號，也是 catalog 資料夾名稱與內容欄位的 key */
  code: string;
  /** 用自己的語言寫的名稱，顯示在選單：繁體中文、English */
  nativeName: string;
  /** 切換開關上的短標籤：中、EN */
  shortLabel: string;
  englishName: string;
  /** 寫入 <html lang> 與元素 lang 的值 */
  htmlLang: string;
  /** 寫入 sitemap 的 xhtml:link 與用戶端 <link rel="alternate" hreflang> 的值 */
  hreflang: string;
  ogLocale: string;
  dir: 'ltr' | 'rtl';
  /** complete：CI 強制無缺字（zh-TW 與 en）；beta：只產生報表，只給日後新增的第三種語言 */
  status: LocaleStatus;
  /** 退回順序，最後一定是基準語系；基準語系本身為空陣列 */
  fallback: readonly string[];
  /** 網址中的語系片段（已決定 D5 的 C 案）：null 代表不帶前綴，只有基準語系可以是 null */
  urlSegment: string | null;
  /** 對應 navigator.languages 的前綴，例如 'zh' 會吃到 zh-TW、zh-Hant、zh-HK */
  match: readonly string[];
  /** 傳給 Intl.* 的 locale */
  intlLocale: string;
  dateStyle: 'long' | 'medium';
  /** 已決定（2026-10-21）：中英介面的金額都顯示 NT$（NT$1,234,000、-NT$1,234,000）。Intl 的 zh-TW 對 TWD 只輸出「$」，所以用 formatToParts 保留數字、千分位與負號，只把 currency 部分換成 symbol */
  money: { mode: 'currency'; symbol: 'NT$' };
  /** 「萬元 / million」寫法的級距，見第 10.4 節；陣列由大到小排列，依序嘗試，第一個能精確表示的級距勝出 */
  compact: readonly { minAbs: number; factor: number; maxFractionDigits: number; pattern: string }[];
  units: Record<UnitKey, UnitPattern>;
}
```

### 2.2 zh-TW 與 en 的設定範例

```ts
// packages/i18n/src/locales.ts
import type { LocaleDef } from './types';

export const LOCALES = [
  {
    code: 'zh-TW',
    nativeName: '繁體中文',
    shortLabel: '中',
    englishName: 'Traditional Chinese (Taiwan)',
    htmlLang: 'zh-TW',
    hreflang: 'zh-TW',
    ogLocale: 'zh_TW',
    dir: 'ltr',
    status: 'complete',
    fallback: [],
    urlSegment: null, // 已決定 D5：中文在根路徑，不帶前綴
    match: ['zh'],
    intlLocale: 'zh-TW',
    dateStyle: 'long',
    money: { mode: 'suffix', suffix: ' 元' },
    compact: [
      // 由大到小排列，格式化函式依序嘗試
      { minAbs: 100_000_000, factor: 100_000_000, maxFractionDigits: 2, pattern: '{n} 億元' },
      { minAbs: 1_000_000, factor: 10_000, maxFractionDigits: 0, pattern: '{n} 萬元' },
    ],
    units: { day: { other: '{n} 天' }, times: { other: '{n} 倍' } },
  },
  {
    code: 'en',
    nativeName: 'English',
    shortLabel: 'EN',
    englishName: 'English',
    htmlLang: 'en',
    hreflang: 'en',
    ogLocale: 'en_GB', // 已決定 D11：英式
    dir: 'ltr',
    status: 'complete',
    fallback: ['zh-TW'],
    urlSegment: 'en', // 已決定 D5：英文在 /en/
    match: ['en'],
    intlLocale: 'en-GB', // 已決定 D11：日期與數字格式跟著英式
    dateStyle: 'long',
    money: { mode: 'currency' },
    compact: [
      { minAbs: 1_000_000_000, factor: 1_000_000_000, maxFractionDigits: 2, pattern: 'NT${n} billion' },
      { minAbs: 1_000_000, factor: 1_000_000, maxFractionDigits: 2, pattern: 'NT${n} million' },
    ],
    units: { day: { one: '{n} day', other: '{n} days' }, times: { other: '{n}×' } },
  },
] as const satisfies readonly LocaleDef[];

/** 語系代號的型別；08 的 ContentSource 也從這裡匯入 */
export type Locale = (typeof LOCALES)[number]['code'];
export const BASE_LOCALE = 'zh-TW' satisfies Locale;
```

說明：

- zh-TW 與 en 從 M0b 起都設成 complete：介面字串數量還少，從第一天起要求每個 PR 同時附上英文，成本最低；介面字串缺翻譯會讓 CI 失敗。內容的強制檢查只套用在已發布的條目：一筆內容只有在中英兩種語言都齊全時才能設為 published，草稿不受影響。若之後英文內容的產量跟不上中文，做法是讓還沒翻譯的條目維持草稿，不是把 en 改成 beta；beta 只給日後新增的第三種語言使用（第 15 節）。content-manifest 的 `locales`（08 第 7.3 節）也應該把 zh-TW 與 en 都寫成 complete。
- `match: ['zh']` 讓 zh-CN、zh-Hans 的使用者也落到 zh-TW。對簡體中文讀者來說，繁體中文仍比英文好讀；若日後加入簡體中文，再把 `match` 拆細。
- `pattern` 裡的 `NT${n}` 是一般字串，不是 JavaScript 的樣板字串，由格式化函式自行代換。
- 建置時檢查登錄檔本身：代號不重複；基準語系是 complete 且沒有退回語系；zh-TW 與 en 都是 complete（beta 只允許日後新增的語系）；每條退回鏈最後都是基準語系，而且沒有循環；`urlSegment` 不重複、全小寫、不和任何路徑字詞（`play`、`chapter`、`level`、`lab`、`terms`、`me` 等）相同，而且只有基準語系可以是 null；`shortLabel` 不超過 3 個字元；`compact` 陣列依 `factor` 由大到小排列。

### 2.4 共用函式

```ts
// packages/i18n/src/match.ts
import { LOCALES, BASE_LOCALE, type Locale } from './locales';

export function getLocale(code: Locale) {
  const def = LOCALES.find((l) => l.code === code);
  if (!def) throw new Error(`Unknown locale: ${code}`);
  return def;
}

/** 依 navigator.languages 的順序找第一個符合的語系，都不符合就用基準語系 */
export function matchLocale(preferred: readonly string[]): Locale {
  for (const tag of preferred) {
    const lower = tag.toLowerCase();
    const hit = LOCALES.find((l) =>
      l.match.some((m) => lower === m.toLowerCase() || lower.startsWith(`${m.toLowerCase()}-`)),
    );
    if (hit) return hit.code;
  }
  return BASE_LOCALE;
}

/** 回傳包含自己在內的退回順序，例如 en 為 ['en', 'zh-TW'] */
export function fallbackChain(code: Locale): Locale[] {
  return [code, ...(getLocale(code).fallback as readonly Locale[])];
}
```

網址的語系片段（已決定 D5 的 C 案）也只在這裡處理，路由、站內連結、語言切換、關卡代號與 App 內掃描（02 第 4.7 節）都呼叫同一組函式：

```ts
// packages/i18n/src/path.ts
import { LOCALES, BASE_LOCALE, type Locale } from './locales';
import { getLocale } from './match';

/** 依路徑的第一段判斷語系：等於某個語系的 urlSegment 就是該語系，否則是基準語系（中文在根路徑） */
export function localeFromPath(pathname: string): Locale {
  const first = pathname.toLowerCase().split('/')[1] ?? '';
  const hit = LOCALES.find((l) => l.urlSegment !== null && l.urlSegment === first);
  return hit ? hit.code : BASE_LOCALE;
}

/** 去掉語系片段，例如 /en/level/lv_k7m2q9xd/ 變成 /level/lv_k7m2q9xd/，/en 與 /en/ 都變成 / */
export function stripLocale(pathname: string): string {
  const seg = getLocale(localeFromPath(pathname)).urlSegment;
  if (seg === null) return pathname;
  const rest = pathname.slice(seg.length + 1);
  return rest === '' ? '/' : rest;
}

/** 替與語系無關的路徑加上語系片段，例如 ('en', '/level/lv_k7m2q9xd/') 變成 /en/level/lv_k7m2q9xd/ */
export function localePath(code: Locale, path: string): string {
  const seg = getLocale(code).urlSegment;
  return seg === null ? path : `/${seg}${path}`;
}
```

- 切換語言時的新網址是 `localePath(新語系, stripLocale(location.pathname))`，再接上原本的查詢字串與 hash。
- 大小寫與結尾斜線的正規化（例如 `/EN/Level/...`、`/en`）由路由在比對前處理，正規化後以 replace 導到正確網址（02 第 1.2 節）；這三個函式只處理語系片段。

格式化函式（第 10 節）與作答輸入正規化（第 11 節）也放在這個套件，都是純 TypeScript，不依賴 React，讓 web、tools 與測試共用同一份實作。佔位符的文法解析放在 `packages/content-schema`，因為它和內容格式綁在一起。

### 3.1 位置與格式

| 項 | 規劃 |
| --- | --- |
| catalog 位置 | 已決定（2026-10-20）：兩份。元件字串放 `packages/web-ui/src/locales/{locale}/messages.po`（第 3.6 節的 `quiz.submit`、多正解題提示、選項狀態字串等都在這裡）；頁面與殼層字串放 `apps/web/src/locales/{locale}/messages.po`。都是 zh-TW 與 en 各一份，commit 進 repo |

Lingui 6 的原生 macro transform（`lingui({ macroTransform: true })`）從 6.9.0（2026-10-01）才提供，官方範例只示範搭配 `@vitejs/plugin-react`。已決定（D5）採 React Router 8 data mode，Vite 外掛就是 `@vitejs/plugin-react`，不使用 framework mode 的 `reactRouter()` 外掛，屬於官方示範的組合；M0a 仍要確認 macro 在實際專案中能正常編譯。「macro transform 與 `reactRouter()` 共存」的驗證【待實測 V09】只在日後改用 framework mode 加預先產生 HTML 時才需要，不行時改用 `@rolldown/plugin-babel` 加 `@lingui/babel-plugin-lingui-macro`。

M0b 驗證結果（2026-10-22）：macroTransform 本身能處理 `packages/web-ui` 的原始碼（web-ui 的字串抽得到，app 建置時 macro 正確轉換），但 `@lingui/vite-plugin` 載入 `.po` 時只接受消費端 `lingui.config` 的 `catalogs.path` 底下的檔案，所以 `apps/web/lingui.config.ts` 要同時列出 web-ui 的 catalog（`path` 指向 `packages/web-ui/src/locales`、`include` 指向 `packages/web-ui/src`）；抽取設定只有 `apps/web` 這一份，web-ui 的 `.po` 仍放在 web-ui 自己的資料夾，日後 `apps/admin` 同樣要列出 web-ui 的 catalog。原本的驗證項目：M0b 要驗證 `@lingui/vite-plugin` 的 macroTransform 能處理 workspace 套件（`packages/web-ui`）的原始碼，抽取與編譯都正確；不行時的退路是把 `packages/web-ui/src` 加進 app 的抽取設定。這是沒有 registry 編號的驗證事項，列在 [14 待確認事項](14-open-questions.md) 第 5.3 節，「`web-ui` 的字串抽取與編譯正確」也是 [10 分階段里程碑](10-milestones.md) M0b 完成標準的結構驗收項目。

### 3.2 寫法

```tsx
import { Trans, Plural } from '@lingui/react/macro';

export function ContinueCard({ dueCount }: { dueCount: number }) {
  return (
    <section>
      <h2>
        <Trans id="home.continue" comment="首頁卡片標題，回到上次未完成的關卡">
          繼續上次
        </Trans>
      </h2>
      <p>
        <Plural id="review.dueToday" value={dueCount} other="今天有 # 題要複習" />
      </p>

```

規則：

- 介面字串裡不寫死金額、百分比或日期。需要時先用第 10 節的格式化函式產生字串，再當成 ICU 參數傳入（例如 `{amount}`）。
- 不用字串串接組句子；一個完整的句子就是一則訊息，讓譯者能調整語序。
- 名詞術語不寫在介面字串裡，改用名詞資料（第 13 節），避免兩邊各寫一份。

### 3.3 ICU 複數

| 訊息 ID | zh-TW（原文） | en（翻譯） |
| --- | --- | --- |
| `review.dueToday` | `{dueCount, plural, other {今天有 # 題要複習}}` | `{dueCount, plural, one {# question to review today} other {# questions to review today}}` |
| `level.progress` | `{current} / {total} 題` | `Question {current} of {total}` |
| `stars.earned` | `{stars, plural, other {得到 # 顆星}}` | `{stars, plural, one {You earned # star} other {You earned # stars}}` |

- zh-TW 在 CLDR 裡只有 other 一種複數分類，en 有 one 與 other。
- `#` 會依目前語系格式化數字。帶小數的數值（例如天數 45.62）不放進 ICU 複數，改用內容格式化的 `unit` 選項（第 10.2 節），因為複數判斷要用和顯示相同的小數位數：`new Intl.PluralRules('en', { minimumFractionDigits: 2 }).select(1)` 是 other（「1.00 days」），不設定小數位數時才是 one。

### 3.4 抽取與 CI 檢查

```yaml
# .github/workflows/ci.yml 的 i18n 步驟（示意，套件名稱以 09 為準）
- name: 抽取介面字串
  run: pnpm --filter @ledgerland/web exec lingui extract --clean
- name: 確認 catalog 已提交
  run: git diff --exit-code -- apps/web/src/locales packages/web-ui/src/locales
- name: complete 語系不得缺字
  run: pnpm --filter @ledgerland/web exec lingui check missing --mode catalog --locale en
- name: 內容翻譯報表
  run: pnpm content:i18n-report
```

- 第一步用 `--clean` 移除已經不用的訊息；第二步確保開發者有把抽取結果 commit 進來。`packages/web-ui` 的 catalog 同樣要抽取、確認已提交並檢查缺字；抽取指令的寫法依 M0b 的 macroTransform 驗證結果決定（第 3.1 節）。
- 第三步一定要用 `--mode catalog`。預設的 resolved 模式與 `lingui compile --strict` 都是在套用退回語系之後才判斷；若設定了退回到 zh-TW，就抓不到 en 的缺漏。
- `--locale` 的清單由腳本從登錄檔產生：所有 complete 且不是基準語系的語系（目前就是 en）。日後新增的 beta 語系另外跑一次並只寫入報表，不讓 CI 失敗。
- `lingui compile` 不加 `--strict` 時允許缺漏翻譯，也不會讓建置失敗；`--strict` 不是預設值，所以 CI 不能依賴「建置成功」代表沒有缺字。

### 3.5 開發期檢查

- 可以設定 Lingui 的 pseudo locale，只在開發環境啟用：所有字串變成加長的假文字，用來找出寫死的字串，並檢查 320px 寬度下的文字溢出。
- 若需要在 JSX 中自動偵測寫死的中文字串，可以只為這個用途另外跑 `eslint-plugin-lingui`（它的 TypeScript peer 是 5 或 6）；是否加入由 09 的工具鏈決定。
- 英文訊息用英式拼字（已決定 D11），由同一份 lint 字表檢查（例如寫成 `color`、`organization` 時提醒改成 `colour`、`organisation`）；字表也用在英文內容。

### 3.6 多正解題的固定提示（已決定 D12）

`multi_choice`（至少兩個正確選項；只有一個正解的題目仍用 `single_choice`）的必填欄位 `scoringMode` 決定作答介面與提示文字。提示是介面字串，不是內容：作者只選 `scoringMode`，不寫提示文字，兩種語言的措辭由 Lingui catalog 統一管理，和其他介面字串一樣由 CI 檢查缺字。題目的語系欄位寫法見第 4.2 節的第二個範例。已決定（2026-10-20）：下表的訊息都是元件字串，放在 `packages/web-ui` 的 catalog（第 3.1 節），網站與後台共用同一份。

| 訊息 ID | 出現的時機 | zh-TW（原文） | en（翻譯） |
| --- | --- | --- | --- |
| `quiz.multi.hint.anyCorrect` | `scoringMode` 為 `any_correct`；單選介面（radio），選中 `correctOptionIds` 任一個即答對 | 這題有不只一個合理答案，選出任一個即可。 | This question has more than one reasonable answer. Choose any one of them. |
| `quiz.multi.hint.allCorrect` | `scoringMode` 為 `all_correct`；核取方塊可複選，按「確認答案」後才判分 | 選出所有正確答案（可複選）。 | Select all the correct answers. You can choose more than one. |
| `quiz.submit` | 作答的共用按鈕：`single_choice`、`multi_choice` 的 `any_correct` 與 `all_correct` 都用同一個按鈕，按下後才判分（03、07） | 確認答案 | Check answer |
| `quiz.choice.status.correctSelected` | 作答後：選了，而且是正確答案 | 正確答案，你選了 | Correct answer, selected |
| `quiz.choice.status.correctMissed` | 作答後：`all_correct` 沒選到的正確答案（漏選） | 正確答案，你沒有選 | Correct answer, not selected |
| `quiz.choice.status.alsoReasonable` | 作答後：`any_correct` 沒選、但也在 `correctOptionIds` 裡的選項 | 也是合理答案 | Also a reasonable answer |
| `quiz.choice.status.wrongSelected` | 作答後：選了，但不是正確答案 | 不是正確答案，你選了 | Not a correct answer, but selected |
| `quiz.choice.status.wrongUnselected` | 作答後：沒選，也不是正確答案 | 不是正確答案 | Not a correct answer |
| `quiz.multi.result.anyCorrectNote` | `any_correct` 答對時的加註 | 這題的其他合理答案也標出來了。 | The other reasonable answers are marked as well. |
| `quiz.multi.result.allCorrectRule` | `all_correct` 答錯時的結果說明 | 要選出所有正確答案，而且沒有選到錯誤的選項，才算答對。 | To get this right, you need to select every correct answer and no incorrect ones. |

設定頁的主題字串（已決定 2026-10-21，見 [16 主題](16-themes.md) 第 7 節；屬於頁面字串，放在 `apps/web` 的 catalog）：`settings.theme.label`（外觀 / Appearance）、`settings.theme.system`（跟隨系統 / Follow system）、`settings.theme.light`（淺色 / Light）、`settings.theme.dark`（深色 / Dark）、`settings.flavor.label`（深色風味 / Dark flavour）、`settings.flavor.violet`（夜空 / Night sky）、`settings.flavor.berry`（莓果 / Berry）、`settings.flavor.wine`（紅酒 / Red wine）。

規則：

- 提示放在選項群組 `<fieldset>` 的 `<legend>` 裡，讓螢幕閱讀器進入選項群組時先唸出作答方式；視覺上以較小的字級顯示在選項上方。`any_correct` 的選項是 radio，`all_correct` 是 checkbox。
- 提示不透露正確答案的數量：這兩則訊息不帶任何 ICU 參數、不用 plural，`comment` 註明「不可加入正確答案的數量」，譯者也不能加。`quiz.multi.result.allCorrectRule` 同樣不寫數量。
- 作答後每個選項都顯示自己的 `feedback`，並標出全部正確答案；`any_correct` 答對時，其他正確選項也一起標示。不給部分分數。標記用文字加圖示，不只靠顏色（07）。
- 按「確認答案」後，焦點移到回饋區的標題，不另外重複 `aria-live` 播報；單選題與多正解題共用的 ChoiceGroup 元件都一樣（03、07）。
- 管理後台（D10(e)）的「判分方式」單選按鈕附說明文字與學習端提示的即時預覽，預覽顯示的就是上表兩則訊息的中英文字，不在後台另寫一份；Excel 範本的「判分方式」下拉欄位只決定 `scoringMode`（見 08）。
- 改動 `scoringMode` 或 `correctOptionIds` 屬於答案改版（`revKind: "answer"`，見 08）；只改提示訊息的措辭是介面字串的修改，不影響任何題目的 `rev`。
- 教材中標示兩個選項都對的那一題（見 01、13），改寫成原創題目時用 `any_correct` 呈現。

## 4. 內容欄位：LocalizedText

### 4.1 型別與 schema

```ts
// packages/content-schema/src/localized.ts（示意）
import { z } from 'zod';
import { LOCALES, BASE_LOCALE, type Locale } from '@ledgerland/i18n';

export type LocalizedText = { readonly [K in typeof BASE_LOCALE]: string } & {
  readonly [K in Exclude<Locale, typeof BASE_LOCALE>]?: string;
};

const nonEmpty = z.string().trim().min(1);

// Zod 4：strictObject 拒絕未宣告的 key
export const LocalizedTextSchema = z.strictObject(
  Object.fromEntries(
    LOCALES.map((l) => [l.code, l.code === BASE_LOCALE ? nonEmpty : nonEmpty.optional()]),
  ),
);
```

- 基準語系 zh-TW 永遠必填，空字串也不行。
- 其他語系在 schema 層級是選填；「內容只有在中英兩種語言都齊全時才能設為 published」（也就是已發布的條目在 complete 語系必須有翻譯）由 i18n 報表與 CI 強制（第 6 節），所以草稿可以只有中文。
- `strictObject` 讓拼錯的語系 key（例如 `zh-tw`、`en-US`）直接驗證失敗。
- 欄位內容是受控標記：純文字、佔位符、粗體、清單與名詞參照，在建置期編譯成 AST，不允許原始 HTML（見 [08 題庫管理](08-content-admin.md)）。

### 4.3 建置後的快照與 ContentSource

content-build 依語系切分快照時，就把退回處理好，學習端只需要讀一份檔案（08 第 7.3 節：非 zh-TW 語系的檔案中，缺翻譯的欄位直接放入 zh-TW 文字並標記退回）。快照中的每個文字欄位都帶著實際語系與是否退回。`contentVersion` 是遞增的整數（對應 08 第 6.4 節的 `content/v{n}`），每個內容檔另有 content hash 檔名。

zh-TW 與 en 都是 complete，上一節那筆缺 en 的題目是草稿，不會進入正式快照；若它在補上英文之前就被設為 published，CI 會失敗，同樣不會進入正式快照。所以在 zh-TW 與 en 的正式快照中，退回只會發生在「萬一漏網」的情況，平常看得到退回的是草稿預覽與日後新增的 beta 語系。下面是這一題（草稿）在草稿預覽建置中的 en 快照示意。實際的 `text` 是 08 第 8 節定義的受控標記 AST，這裡為了好讀，用原文字串示意：

```json
{
  "schemaVersion": 1,
  "contentVersion": 12,
  "locale": "en",
  "questions": [
    {
      "id": "q_3hf8k2wm",
      "rev": 2,
      "prompt": {
        "text": "The company pays {{money:vars.cash}} in cash for a piece of equipment. What happens to {{term:tm_c4sh8k2p}}?",
        "lang": "en",
        "isFallback": false
      },
      "explanation": {
        "text": "付出現金，{{term:tm_c4sh8k2p}}減少 {{money:vars.cash}}；{{term:tm_e9qp3m7r}}增加同樣的金額，所以資產總計不變，答案是{{option:o_k3x9}}。",
        "lang": "zh-TW",
        "isFallback": true
      }
    }
  ]
}
```

執行期的 ContentSource（唯讀，見 08 第 7.4 節）把每個文字欄位交給元件時，使用 08 第 7.4 節與 04 共用的同一個型別 `ResolvedText`：

```ts
import type { Locale } from '@ledgerland/i18n';
import type { CompiledMarkup } from './markup'; // 08 第 8 節的受控標記 AST

// 與 08 第 7.4 節相同，定義只放一處（packages/content-schema），這裡列出來方便對照
export interface ResolvedText {
  text: CompiledMarkup; // 已編譯的 AST
  lang: Locale;         // 這段文字真正的語系
  isFallback: boolean;  // true 代表退回 zh-TW，元件要標示「尚未翻譯」並設定 lang
}
```

元件只依 `ResolvedText` 渲染，不自己判斷退回，這樣介面與內容的退回規則就不會混在一起。

## 5. 缺翻譯的退回與標示

| | 介面字串（Lingui） | 內容欄位（LocalizedText） |
| --- | --- | --- |
| 建置期檢查 | `lingui check missing --mode catalog`，complete 語系缺字就讓 CI 失敗 | i18n 報表，已發布條目在 complete 語系缺字就讓 CI 失敗 |
| 執行期退回 | 編譯後缺字的訊息顯示 zh-TW 原文 | 依退回鏈取第一個有值的語系 |
| 執行期能否知道哪一則退回 | 不能（編譯後無從得知） | 能（快照中有 `isFallback` 標記） |
| 標示方式 | 語言切換處的語系名稱旁標「Beta」；第一次切換到 beta 語系時顯示一次說明 | 每個退回的元素旁標「尚未翻譯」，元素設定 `lang="zh-TW"` |
| 適用語系 | 只有日後新增的 beta 語系會發生（zh-TW 與 en 從 M0b 起是 complete，有 CI 保證） | 任何語系的草稿預覽、日後新增的 beta 語系，以及 complete 語系萬一漏網的情況 |

### 5.1 介面字串的 Beta 說明

- 本節只適用日後新增、狀態為 beta 的第三種語言；zh-TW 與 en 是 complete，不會出現 Beta 標籤與說明。
- 第一次切換到 beta 語系時，顯示一次可關閉的提示：「部分介面尚未翻譯，暫以中文顯示」（以目標語系顯示；若這則提示本身也沒翻譯，就會以中文出現，同樣能讓使用者看懂）。
- 已看過的紀錄存在 localStorage，之後不再出現；語言選單上的「Beta」標籤則一直保留。

### 5.2 內容的「尚未翻譯」標記

- 標記是一個小 chip，文字用目前的介面語言（英文介面為 "Not yet translated"），按下去說明「這段內容還沒有英文版，先顯示中文」。
- 退回的元素本身設定 `lang="zh-TW"`，螢幕閱讀器才會用中文語音唸，瀏覽器也會選用正確的中文字形。
- 同一個畫面退回的元素很多時（例如整章都還沒翻譯），改在畫面頂部顯示一次「本頁部分內容尚未翻譯」，元素上只保留 `lang` 與不顯眼的圖示，避免畫面被標記淹沒。
- 退回文字裡的佔位符依「這段文字的語系」格式化：英文介面中退回的中文解說，金額顯示為「NT$120,000」（兩種語系的金額寫法相同，只有 `|compact` 的萬元與 million 不同），名詞 chip 顯示中文名稱，但點開名詞卡時仍用英文介面。這樣同一句話裡不會出現中英格式混雜。
- 選項文字若有退回，選項的順序與 ID 不變，計分也不受影響。

## 7. 網址策略（已決定 D5）

已決定（D5，2026-10-20）：C 的網址形狀（中文在根路徑、英文在 `/en/`），搭配原本 A 案的技術路線（React Router 8 data mode 加 vite-plugin-pwa，不預先產生 HTML）。第 7.1 到 7.3 節是決定前的比較紀錄，表中「C 案」指的是原本「C 的網址加預先產生 HTML」的組合，所以預先快取、主機退路與實作複雜度那幾列的 C 欄不代表目前的做法；目前的做法以第 7.4 節為準。

### 7.1 三個方案（決定前的比較紀錄）

- **A 不帶前綴**：所有語言共用同一組網址（例如 `/level/lv_k7m2q9xd/`），語系存在本機偏好，切換時由瀏覽器端更新 `html lang`。框架用 React Router 8 data mode 加 vite-plugin-pwa。
- **B 全站前綴**：`/zh-TW/level/lv_k7m2q9xd/`、`/en/level/lv_k7m2q9xd/`，公開頁面預先產生靜態 HTML。框架用 React Router 8 framework mode（`ssr: false` 加 prerender），Service Worker 改在建置後用 workbox-build 產生。根路徑 `/` 的行為另有三個子選項（第 7.3 節）。
- **C 中文在根路徑**：中文是 `/level/lv_k7m2q9xd/`，英文是 `/en/level/lv_k7m2q9xd/`，同樣預先產生 HTML，框架與 B 相同。

### 7.2 比較（決定前的比較紀錄）

| 比較面向 | A 不帶前綴 | B 全站前綴 | C 中文在根路徑 |
| --- | --- | --- | --- |
| 搜尋收錄與 hreflang | 每頁只有一個網址，無法用 hreflang 區分語言；初始 HTML 只有殼層，要靠搜尋引擎執行 JavaScript。爬蟲看到哪種語言不可控（依瀏覽器語言判斷時，語言設定為英文的爬蟲可能只看到英文版） | 每種語言各有網址與靜態 HTML，可以完整標示 hreflang 與 x-default；符合 Google「不同語言用不同網址、避免依語言自動轉址」的建議 | 同 B；x-default 指向中文版 |

| 預先快取體積 | 最小：一份殼層 HTML、兩種語言的 catalog 與內容 JSON | 最大：每個預先產生的頁面在每種語言各有 HTML 與 `.data`，同一段文字會出現在 HTML、`.data`、內容 JSON 三處；名詞頁約 375 筆（底稿約 300 筆）時要嚴格挑選與設定預算 | 同 B |

### 7.3 B 案的根路徑子選項（未採用，濃縮紀錄）

B 案的根路徑原本有三個子選項：B-1 可收錄的語言選擇頁（符合 Google 建議，但從根路徑進來的人多一步，主畫面 App 以 `/` 為 start_url 時每次都看到選擇頁）；B-2 直接顯示 zh-TW 並提示可切換（根路徑與 `/zh-TW/` 內容重複，要用 canonical）；B-3 只依已存偏好在瀏覽器端轉址（回訪者直接進入自己的語言，但單獨使用時沒有定義第一次造訪的行為）。「沒有偏好時依瀏覽器語言自動轉址」違反 Google 避免依語言自動轉址的建議，從一開始就不列為選項。決定 C 之後，根路徑直接是中文首頁，只保留 B-3 的「依已存偏好轉址」行為（第 7.4 節第 3 點），本案沒有語言選擇頁。

### 7.4 決定後的做法（C 的網址，不預先產生 HTML）

選擇理由：主要入口是課堂 QR、LINE 群組連結與主畫面 App；C 的中文網址和 A 一樣短、根路徑直接是內容、連結本身帶有語言，英語授課的老師可以直接印英文網址的 QR。主機採 Cloudflare Workers（D4），SPA fallback 可以讓 `/en/` 的深層連結也回到殼層並給 200，所以不必為了網址形狀而採用整合風險最高的 framework mode 加 prerender。

1. **網址形狀**：中文 `/<路徑>`，英文 `/en/<路徑>`；中文首頁 `/`，英文首頁 `/en/`。路徑字詞與 ID 在兩種語言完全相同，一律小寫、帶結尾斜線。語系片段只由第 2.4 節的 `localeFromPath`、`stripLocale`、`localePath` 處理。
2. **路由**：React Router 8 data mode 的 `createBrowserRouter`，中文的子路由掛在 `/`，英文的同一組子路由掛在 `/en`，由同一個函式依語系產生，頁面元件共用。語言由網址決定，root layout 依 `localeFromPath()` 啟用 Lingui 的語系與內容快照。
3. **根路徑**：只有 `/` 這一個網址依已存偏好轉址：localStorage 的 `ll:locale` 為 en（使用者主動選過）時，head 裡的 boot 腳本在建立路由之前以 `history.replaceState` 把網址換成 `/en/`，同時把 `html lang` 設成 en，不多一次請求，也不會先閃過中文。沒有偏好時（包括所有爬蟲）就是中文首頁。主畫面 App 的 `start_url` 是 `/`（06），所以選過英文的人從主畫面開啟時直接進到英文首頁。
4. **殼層與 fallback**：建置輸出一份殼層 `index.html`。Cloudflare Workers Static Assets 設 `not_found_handling = "single-page-application"`，任何沒有對應檔案的導覽請求（包括 `/en/` 開頭）都回傳這份殼層並給 200。殼層不是語言選擇頁；本案沒有語言選擇頁，fallback 不得回傳語言選擇頁。Service Worker 用 vite-plugin-pwa 的 generateSW，離線導覽的 fallback 也是 `index.html`（06、09）。
5. **`html lang`**：殼層寫 `lang="zh-TW"`，boot 腳本在第一次繪製前依路徑改成正確值（第 9.1 節）。
6. **hreflang 與收錄**：建置時由 `tools/` 依 content-manifest 產生 `sitemap.xml`，列出 02 第 1.1 節「列入 sitemap」的頁面，中英網址互列 hreflang，x-default 指向中文（第 9.3 節）。初始 HTML 只有殼層，搜尋引擎要執行 JavaScript 才看得到內容；用戶端渲染後在 head 寫入 canonical 與 hreflang，但不依賴它。
7. **分享預覽**：LINE 與社群網站產生預覽時通常不執行 JavaScript，所以所有頁面（中英相同）共用殼層裡同一組 og 標籤：`og:locale` 為 zh_TW，`og:locale:alternate` 為 en_GB。
8. **語言切換**：以 replace 導到另一種語言的同一頁（第 8.5 節），作答狀態在路由外的 store，不受影響；兩種語言的 catalog 與內容快照都在預先快取中，離線也能切換，不需要任何 `.data` 檔。
9. **大小寫與斜線**：SPA fallback 對不存在的檔案直接回傳殼層，所以 `/EN/...`、`/en`、少了結尾斜線的網址都由用戶端路由轉成小寫、補上斜線後以 replace 導到正確網址；猜測的 `/zh-tw/`、`/zh/` 開頭以 replace 導到去掉這一段的中文網址。
10. **日後加強收錄**：若 M8 前後希望名詞頁等公開頁被搜尋收錄得更好，或分享預覽要顯示頁面名稱，再評估預先產生 HTML（React Router framework mode 的 prerender，或自寫只產生少數公開頁的小型腳本）。網址不必改，已印出的 QR 都還能用；屆時程式要從 data mode 改成 framework mode、Service Worker 改成建置後產生，並驗證【待實測 V08】【待實測 V09】【待實測 V15】，也要重新計算預先快取的預算。

### 7.5 必須達成的條件

- 作答中切換語言時，題目 ID、已選選項、計時與捲動位置都保留（作答狀態放在 store，不綁在路由參數上）。Playwright 的 E2E 測試要涵蓋這一條。
- 站內連結一律帶結尾斜線，路徑字詞用英文小寫；英文連結一律由 `localePath()` 產生。
- 課堂 QR 的落地頁不出現語言選擇（見 02 第 4.3 節）；`/en/` 開頭的深層連結經由 SPA fallback 開啟時，第一次繪製前 `html lang` 就是 en。
- Cloudflare 的 SPA fallback 回傳的是殼層 `index.html`，不是任何語言選擇頁（M0a 檢查）。

來源：https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/ 、https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites （查證日期 2026-10-20）

## 8. 語言切換的使用者體驗

### 8.1 元件

- 由登錄檔的語系數量決定：兩種語言時是分段式切換開關（`中 | EN`），三種以上自動改成選單按鈕，打開後列出各語系的自稱名稱。
- 切換開關的語意是一組單選按鈕（`role="radiogroup"`，標籤「語言」或 "Language"），每個選項用自己的語言寫，並設定自己的 `lang`（例如 `<span lang="en">EN</span>`），可讀名稱為「繁體中文」與「English」。
- beta 語系（只有日後新增的第三種語言）在名稱旁顯示「Beta」標籤；zh-TW 與 en 是 complete，不顯示。
- 觸控範圍至少 44×44px。

### 8.2 位置

| 位置 | 原因 |
| --- | --- |
| 首頁頂部列 | 第一個畫面就看得到，不必找 |
| 關卡作答頁頂部列 | 中英對照是學會計英文的實際用法，作答中切換要很方便 |
| 實驗室步驟頁頂部列 | 同上 |
| 我的 → 設定 | 完整的語言設定與說明（包括名詞卡是否雙語顯示） |
| expanded 以上的側邊欄底部 | 寬螢幕上固定可見 |

### 8.3 語言的判斷順序（已決定 D5 的 C 案）

| 順序 | 判斷 | 說明 |
| --- | --- | --- |
| 1 | 網址：`/en/` 開頭為 en，其餘為 zh-TW（`localeFromPath()`） | 每一頁的語言都由網址決定，第一次造訪與回訪都一樣 |
| 2 | 只有根路徑 `/`：已存偏好 `ll:locale` 為 en 時，boot 腳本以 `history.replaceState` 換成 `/en/` | 讓主畫面 App（`start_url` 為 `/`）與回訪者直接進入英文；爬蟲沒有偏好，不受影響；其他網址一律不依偏好轉址 |
| 3 | `navigator.languages` 依序比對登錄檔的 `match` | 只用來決定要不要顯示切換提示，不改變目前的語言 |

- 整個過程不跳出語言選擇對話框，也沒有語言選擇頁。
- 若網址決定的語言和已存偏好或瀏覽器語言不同（例如英文瀏覽器掃到中文 QR、選過英文的人點了別人分享的中文連結），在頁面頂部顯示一次可關閉的小提示，不擋內容；每個工作階段最多一次。提示用目標語言寫，讓看不懂目前語言的人也看得懂：

| 訊息 ID | 何時顯示 | 文字（以目標語言顯示） |
| --- | --- | --- |
| `locale.suggest.en` | 目前是中文網址，偏好或瀏覽器語言是英文 | Prefer English? Switch |
| `locale.suggest.zhTW` | 目前是 `/en/` 網址，偏好或瀏覽器語言是中文 | 要改看中文嗎？切換 |

- 這兩則訊息要從目標語言的 catalog 取字：要顯示提示時才另外載入目標語言的 catalog（兩種語言的 catalog 都在預先快取中，第 3.1 節），載入失敗就不顯示提示。提示元素設定目標語言的 `lang`。按下「Switch」或「切換」等於按語言切換開關（第 8.5 節），會寫入偏好。
- 關卡代號與 App 內掃描課堂 QR（02 第 4.7 節）導向時沿用目前的介面語言，不因為 QR 本身是中文或英文網址而切換語言。

### 8.4 記住選擇

- 只記住使用者主動切換的結果，以 IndexedDB 的 `settings` 為準（備份檔帶的是這一份），另外同步鏡像到 localStorage 的 `ll:locale`，讓 boot 腳本在第一次繪製前同步讀取、處理根路徑的轉址（06 第 4.1 節）。
- 網址決定的語言不寫入偏好；只是開啟另一種語言的網址（例如掃到 `/en/` 的 QR）不會改變偏好。
- 瀏覽器語言從來不寫入偏好，只影響切換提示。

### 8.5 切換時發生的事

1. 使用者按下另一個語言。
2. 動態載入該語系的 catalog 與內容快照（都在 precache 裡，離線也可以）。載入完成前，畫面維持原本的語言，不出現空白。若真的載入失敗（例如還沒快取），保留原語言並提示「這個語言的內容還沒下載完成」。
3. 記錄捲動錨點：畫面最上方元素的 ID 與偏移量。
4. 啟用新語系：Lingui `i18n.activate`、更新 store、`document.documentElement.lang` 與 `dir`、頁面標題；殼層裡的 Tab bar 只改標籤文字與 `href`，不替換 `nav` 或任何子元素（07 第 6.1 節）。同時以 replace 方式導到另一種語言的同一頁：新網址是 `localePath(新語系, stripLocale(目前路徑))`，查詢字串（例如 `?term=`、`?from=`、`?mode=practice`）與 hash 保留。用 replace 是為了讓按返回時語言不會切回去；head 裡的 canonical 與 hreflang 也一併更新（第 9.3 節）。
5. 依錨點還原捲動位置（兩種語言的文字高度不同，不能直接用 scrollY；M0b 的示範頁先以 scrollY 還原、E2E 只斷言捲動沒有被重設，錨點式還原在 M2 隨正式作答頁實作）；焦點留在切換開關上；用 `aria-live="polite"` 以新語言播報「Language: English」或「語言：繁體中文」。
6. 作答狀態完全不動：題目 ID、選項順序（由種子與選項 ID 決定，與文字無關）、已選選項、數字題的原始輸入、是否已按「確認答案」、計時器。若載入超過約 300 毫秒，計時器在載入期間暫停。
7. 寫入偏好。

## 9. `html lang`、元素 `lang` 與 hreflang

### 9.1 `html lang`

- 值取自登錄檔的 `htmlLang`（zh-TW、en），跟著網址的語言，切換語言時同步更新。
- 已決定（D5）不預先產生 HTML，所有網址都由同一份殼層開啟：殼層寫 `lang="zh-TW"`，head 內的 boot 腳本在第一次繪製前依路徑的語系片段改成正確值（`/en/` 開頭為 `en`）；根路徑 `/` 依已存偏好換成 `/en/` 時，同一段腳本也把 `lang` 設成 `en`。這段腳本由建置腳本依登錄檔產生，和 06 第 2.3 節的 boot 腳本（寫入 `data-theme`、`data-display`、`data-glass`、`data-motion`，玻璃層級見 07）合併成一段，並納入 CSP 的 sha256【待實測 V15】。
- 殼層裡另有第二段 inline 腳本：緊接在 `<nav id="ll-tabbar">` 之後的殼層在地化腳本（已決定 D8：Tab bar 寫在初始 HTML 殼層，見 06 第 2.3 節、07 第 6.1 節）。殼層的 `nav` 內含完整的五個連結、圖示與中文標籤；英文網址時，這段腳本在第一次繪製前把標籤、`href` 與 `aria-label` 換成英文（「跳到主要內容」連結的文字也一起改寫）。殼層的中文標籤、這段腳本裡的英文標籤與 Lingui catalog 的 Tab 標籤訊息是同一組名稱（D9）。React 不建立也不替換 `nav` 與其子元素，只更新 `aria-current`、標籤文字、`href` 與收合狀態，不使用 React portal。
- CSP 的 `script-src` 列出這兩段 inline 腳本（head 的 boot 腳本、`nav` 之後的殼層在地化腳本）的 sha256，CI 檢查兩段的雜湊（09 第 11 節）【待實測 V15】。
- 經由 SPA fallback 開啟的 `/en/` 深層連結，第一次繪製前 `lang` 就必須是 `en`（M0a 的檢查項目）；頁面標題 `document.title` 由 app 渲染時依語言設定。
- 用戶端沒有執行 JavaScript 時（例如分享預覽的爬蟲），只會看到殼層的 `lang="zh-TW"`，這是不預先產生 HTML 的已知限制（第 7.4 節第 7 點）。

### 9.2 元素層級的 `lang`

| 情況 | 設定 |
| --- | --- |
| 退回的內容（英文介面中的中文解說） | `lang="zh-TW"` |
| 名詞卡上另一種語言的術語 | 例如中文介面的英文術語設 `lang="en"` |
| 語言切換開關的選項文字 | 各自的 `lang` |
| 英文介面中顯示教材原文的地方（例如名詞卡的「教材用語」） | `lang="zh-TW"` |

`lang` 也影響字形：同一個漢字在繁體中文、日文的字形不同，瀏覽器依 `lang` 選字型，所以不能省略。

### 9.3 hreflang 與 sitemap（已決定 D5：sitemap 為主）

不預先產生 HTML，每個網址的初始 HTML 都是同一份殼層，所以 hreflang 以建置時產生的 `sitemap.xml` 為主。sitemap 由 `tools/` 依 content-manifest（已發布的章節、名詞等）與固定頁面清單產生，只列 02 第 1.1 節「列入 sitemap」的頁面；每個頁面的中文與英文網址各一筆 `<url>`，兩筆都列出完整的語言版本與 x-default（指向中文）：


- og 標籤寫在殼層，所有頁面共用一組（`og:locale` 為 zh_TW、`og:locale:alternate` 為 en_GB，已決定 D11），原因見第 7.4 節第 7 點。

## 10. 格式化

### 10.1 佔位符文法

本文件是佔位符文法的依據，04 與 08 都引用這裡。

```
placeholder = "{{" type ":" ref [ "|" option *( "," option ) ] "}}"
type        = "money" / "percent" / "number" / "date" / "term" / "option" / "ratio" / "raw"
ref         = value-ref / id-ref / raw-text
value-ref   = "vars." name                      ; 題目自帶的數字（題目的 vars）
            / event-id "." name                 ; 事件參數或推導值，例如 e1.price
            / "expected." target-id "." name    ; 核心算出的答案，例如 expected.t1.delta
            / "param." name                     ; 只在交易範本的 summary 與 explanation：本範本的參數
            / "derived." name                   ; 只在交易範本的 summary 與 explanation：本範本的推導值
            / "amount"                          ; 只在核心 effects 的片語樣板：這一筆 effect 的金額
            / number-literal                    ; 固定值，例如門檻值 0.5
id-ref      = name [ "@" name ]                 ; tm_ 名詞 ID、o_ 選項 ID、指標 ID@版本
option      = key [ "=" value ]                 ; 例如 compact、digits=2、unit=day、sign
```

- `money`、`percent`、`number`、`date` 的 ref 一律是 value-ref；`term` 與 `option` 是不帶 `@` 的 id-ref；`ratio` 是帶 `@` 的 id-ref；`raw` 是 raw-text（不含 `}}` 與 `|` 的文字）。`vars`、`expected`、`param`、`derived`、`amount` 是保留字，不能當事件 ID。
- 文法本身接受所有 value-ref，但每種寫法只能用在自己的作用範圍；超出作用範圍的佔位符由驗證器回報錯誤（第 10.5 節第 2 條）。

數值類 ref 的作用範圍分三種：

| 作用範圍 | 涵蓋的文字 | 可用的 ref |
| --- | --- | --- |
| 一般內容 | 題目、選項、回饋、解說、故事步驟、名詞卡、實驗室說明等內容文字 | `vars.<name>`、`<eventId>.<參數或推導值>`、`expected.<targetId>.<欄位>`、數字字面值 |
| 交易範本 | 交易範本（`tpl.` 開頭）的 `summary` 與 `explanation`（04 第 7 節） | 一般內容的寫法，另加 `param.<name>`、`derived.<name>`；範本本身沒有 `vars`、事件與 target，所以實際上能通過引用檢查的只有 `param.*`、`derived.*` 與數字字面值 |
| 片語樣板 | 核心產生 `effects` 文字用的片語樣板（04 第 6.5 節） | 一般內容的寫法，另加 `amount`；片語樣板不屬於任何題目或步驟，所以實際上能通過引用檢查的只有 `amount` 與數字字面值 |

數值類 ref 的寫法：

| ref 寫法 | 值從哪裡來 | 作用範圍 | 例子 |
| --- | --- | --- | --- |
| `vars.<name>` | 題目的 `vars`，也就是題目自帶的數字（例如 `{ "loan": 240000 }`） | 一般內容 | `{{money:vars.loan}}` |
| `<eventId>.<參數或推導值>` | 計算型題目 `scenario.events[]`（或故事步驟的 `events[]`）中該事件的 `params`，以及交易範本算出的推導值；事件 ID 在題目或步驟內唯一，寫成 `e1`、`e2` | 一般內容 | `{{money:e1.price}}` |
| `expected.<targetId>.<欄位>` | 核心依 `scenario.targets` 算出、寫入快照的答案；`targetId` 是 target 的 `id`，欄位名稱依 04 第 15 節的答案型別（例如 `delta`） | 一般內容 | `{{money:expected.t1.delta}}` |
| `param.<name>` | 本範本 `params` 中宣告的參數；交易卡顯示在故事或題目中時，由核心代入該事件的值（等同那裡的 `e1.<name>`） | 交易範本 | `{{money:param.price}}` |
| `derived.<name>` | 本範本 `derived` 中宣告的推導值；顯示時同樣由核心代入該事件算出的值 | 交易範本 | `{{money:derived.costOfAllInventory}}` |
| `amount` | 核心替每一筆 effect 提供的區域值，也就是同一筆 effect 的 `amount` 欄位 | 片語樣板 | `{{money:amount}}` |
| 數字字面值 | 文字本身 | 三種範圍都可用 | `{{percent:0.5}}` |

| type | ref 指向 | 可用選項 | 預設 |
| --- | --- | --- | --- |
| `money` | 整數金額（精度依帳本的 scale，TWD 為 0） | `compact`、`sign` | 完整數字 |
| `percent` | 比率值（0.0734 代表 7.34%） | `digits=N`、`sign` | `digits=2` |
| `number` | 數值 | `digits=N`、`unit=day`、`unit=times`、`sign` | 依數值本身，無單位 |
| `date` | ISO 日期字串（YYYY-MM-DD） | `style=long`、`style=medium` | 登錄檔的 `dateStyle` |
| `term` | `tm_` 名詞 ID（例如 `tm_n7v3k8pq`） | `plain`（只輸出文字，不做成 chip） | 名詞 chip |
| `option` | 本題的 `o_` 選項 ID（例如 `o_k3x9`） | 無 | 該選項在這段文字語系的文字；選項打散順序後仍顯示正確的文字（選項 ID 規則見 08 第 4.3 節） |
| `ratio` | 指標 ID 加版本（例如 `roa@excel`） | 無 | 指標名稱與該版本的公式；語意定義見 04，08 第 8.1 節提議 |
| `raw` | 原樣輸出的文字（例如年份、準則條號） | 無 | 無；只能用在 08 第 8.1 節的白名單情境 |

- 數值類的 `ref` 只能是上表的寫法之一，而且必須符合文字所在的作用範圍；`vars.*`、事件與 target 都必須在這筆內容中宣告過，`param.*`、`derived.*` 必須在同一個範本的 `params`、`derived` 中宣告過（第 10.5 節第 2 條）。數字字面值用在門檻值這類固定值，讓兩種語言用同一個值格式化。
- 題目與故事的文字要引用交易參數時寫 `{{money:e1.price}}`，不寫 `{{money:param.price}}`；`param.*`、`derived.*`、`amount` 是範本與片語樣板內的區域寫法，由核心代換成該事件或該筆 effect 的值（見 04 第 6.5、16.1 節）。
- `expected.*` 帶出的是答案，通常只用在解說與回饋。
- `sign` 是變動值選項（例如 `{{money:expected.t1.delta|sign}}`、`{{percent:vars.change|sign}}`）：正數帶「+」、負數帶「-」，0 與四捨五入後為 0 的值不帶正負號，格式化前同樣把 -0 改成 0（第 10.3 節）。它用在 07 第 2.5 節的變動徽章這類「顯示變動量」的地方，是本文件與 04 第 12.6 節「所有數字格式器一律 `signDisplay: 'negative'`」的唯一例外。`sign` 可以和 `digits`、`unit` 並用，不和 `compact` 並用（變動值一律顯示完整數字）。
- 本文件定義 `money`、`percent`、`number`、`date`、`term`（含 `|plain`）與 `option` 的格式化與渲染規則；`ratio` 的語意由 04 定義、08 第 8.1 節提議，這裡列入文法，讓驗證器用同一套文法解析。
- `raw` 是逃生口，用來包住會被「寫死數字」檢查誤判、但不是數量的文字，例如年份 `{{raw:2027}}`、準則條號。報表會統計使用次數，審稿時逐一確認。
- 佔位符不能巢狀，也不能出現在名詞 ID 裡。

### 10.3 Intl 設定

| 用途 | 設定 | 說明 |
| --- | --- | --- |
| 金額（zh-TW 與 en 相同） | `style: 'currency'`、`currency: 'TWD'`、`currencyDisplay: 'symbol'`、`minimumFractionDigits` 與 `maximumFractionDigits` 都等於 scale（TWD 為 0）、`signDisplay: 'negative'`、`numberingSystem: 'latn'`，再用 `formatToParts` 把 `currency` 部分換成 `NT$` | 已決定（2026-10-21，M0a 實測後）：中文介面也顯示 NT$。Intl 的 zh-TW 對 TWD 只輸出「$」，en-GB 才輸出「NT$」，所以兩種語系都只信任 Intl 的數字、千分位與負號，幣別符號自己放；結果是 `NT$1,234,567`、`-NT$1,234,567`，-0 先改成 0 顯示 `NT$0`。TWD 的預設是 2 位小數，一定要明確設成 0 |
| 報表與輸入框 | `style: 'decimal'`、千分位、小數位數等於 scale、`signDisplay: 'negative'` | 幣別寫在表頭（「單位：NT$」、"Unit: NT$"）；負數一律用負號，不用括號，以免和教材的「(-)」列名混淆 |
| 百分比 | `style: 'percent'`、`minimumFractionDigits` 與 `maximumFractionDigits` 都等於 digits（預設 2）、`signDisplay: 'negative'` | 顯示精度與計分容許誤差見 04 |
| 一般數值 | `style: 'decimal'`、依佔位符的 digits、`signDisplay: 'negative'` | |
| 變動值（`\|sign` 選項，07 的變動徽章） | 依數值種類沿用上面金額、報表、百分比或一般數值的設定，只把 `signDisplay` 改成 `'exceptZero'`；格式化前同樣把 -0 改成 0 | 正數帶「+」、負數帶「-」，0 與四捨五入後為 0 的值不帶正負號（例如 `+12,000`、`-12,000`、`0`）。這是「一律 `signDisplay: 'negative'`」（本節與 04 第 12.6 節）的唯一例外，只用在顯示變動量的地方；報表本身的數值與輸入框不用 |
| 日期（日曆日） | `Intl.DateTimeFormat`，`dateStyle` 依登錄檔或佔位符、`timeZone: 'UTC'` | ISO 日期字串會被解析成 UTC 午夜，不指定 UTC 時，某些時區會顯示成前一天 |
| 時間點（例如錯題本的下次複習時間） | 本地時區 | |
| 複數 | `Intl.PluralRules`，小數位數和顯示時相同 | 見第 3.3 節 |

共同規則：

- 格式化前遇到 `Object.is(v, -0)` 就改成 0；所有數字格式器都加 `signDisplay: 'negative'`，四捨五入後變成 -0.00 的值才會顯示成「0.00%」。查證時確認：不加的話，-0.0000004 會顯示成「-0.00%」。唯一例外是變動值（`|sign`）改用 `'exceptZero'`，它同樣不會輸出「-0.00%」或「+0」（第 10.2 節的範例）。
- 不使用 `currencyDisplay: 'name'`（V8 輸出「新台幣」、JavaScriptCore 輸出「元」，兩個引擎不同）。
- 不使用 `notation: 'compact'`：查證時 2,485,000 在 zh-TW 變成「249萬」、在 en 變成「2.5 million」，兩種語言的數值已經對不上。
- 測試不要跨引擎比對格式化後的字串，改用 `formatToParts`，或每個引擎各自建立快照。
- 格式器實例依「語系加選項」快取，不要每次重建。

```ts
// packages/i18n/src/format.ts（示意）
import { getLocale } from './match';
import type { Locale } from './locales';

const cache = new Map<string, Intl.NumberFormat>();

function nf(locale: string, opts: Intl.NumberFormatOptions): Intl.NumberFormat {
  const key = `${locale}|${JSON.stringify(opts)}`;
  let f = cache.get(key);
  if (!f) {
    f = new Intl.NumberFormat(locale, { numberingSystem: 'latn', signDisplay: 'negative', ...opts });
    cache.set(key, f);
  }
  return f;
}

const noNegZero = (v: number) => (Object.is(v, -0) ? 0 : v);

/** |sign 選項：變動值改用 exceptZero（正數帶 +，0 不帶正負號），是 signDisplay: 'negative' 的唯一例外 */
const signOpt = (sign: boolean): Intl.NumberFormatOptions => (sign ? { signDisplay: 'exceptZero' } : {});

export function formatMoney(value: number, code: Locale, scale = 0, sign = false): string {
  const def = getLocale(code);
  const opts = { minimumFractionDigits: scale, maximumFractionDigits: scale, ...signOpt(sign) };
  // 已決定（2026-10-21）：兩種語系都顯示 NT$。只信任 Intl 的數字、千分位與負號，currency 部分換成登錄檔的 symbol
  const parts = nf(def.intlLocale, { style: 'currency', currency: 'TWD', currencyDisplay: 'symbol', ...opts }).formatToParts(noNegZero(value));
  return parts.map((p) => (p.type === 'currency' ? def.money.symbol : p.type === 'literal' ? '' : p.value)).join('');
}
```

### 10.4 「萬元 / million」規則

中文的完整金額已改顯示 `NT$`（2026-10-21），但 `|compact` 的縮寫仍用「萬元」「億元」：教材與口語都這樣講，「NT$248 萬」反而不自然。

- 只有加上 `|compact` 的 `money` 佔位符可以使用，而且每個 complete 語系都必須找得到能精確表示的級距，否則建置失敗。不會悄悄改用完整數字，作者必須自己改寫。
- 級距定義在登錄檔（第 2.2 節）。每個語系由大到小嘗試：絕對值達到 `minAbs`，而且「金額 ÷ factor」的小數位數不超過 `maxFractionDigits`，就用這個級距。
  - zh-TW：1 億以上先試「億元」（最多 2 位小數，也就是 1,000,000 的整數倍），不行再試「萬元」（整數，也就是 10,000 的整數倍）；100 萬以下不允許。教材同時使用「萬」與「億」，所以兩種都支援。
  - en：10 億以上用 billion，100 萬以上用 million，都最多 2 位小數。
  - 實際效果：金額必須是 10,000 的整數倍，而且絕對值不小於 1,000,000。10,000 的整數倍除以 1,000,000，小數一定不超過 2 位，所以英文一定能精確表示；中文的萬級距也一定可以。
- 實作不用 Intl 的 compact：把「金額 ÷ factor」用 decimal 樣式格式化（保留千分位、`maximumFractionDigits` 依級距），再代入 `pattern`。負數為「-248 萬元」與「-NT$2.48 million」。
- 報表、輸入框與作答回饋一律用完整數字，不用 compact。

### 10.5 驗證器規則

由 `content:check`（以及發布前的 `content:compile`）執行：

1. **語法**：每個佔位符都能解析，type 已知，選項合法（例如 `sign` 只能用在 `money`、`percent`、`number`，而且不能和 `compact` 並用）。
2. **引用存在與作用範圍**：`vars.<name>` 在題目的 `vars` 中有宣告；`<eventId>.<欄位>` 的事件存在於 `scenario.events`（或故事步驟的 `events`），欄位是該事件的參數或交易範本的推導值；`expected.<targetId>.<欄位>` 的 target 存在於 `scenario.targets`，欄位是核心會寫入快照的答案欄位；名詞 ID 存在而且已發布；選項 ID 屬於同一題；指標 ID 與版本存在於 04 的指標登錄檔。作用範圍（第 10.1 節）依欄位所在的位置檢查：
   - 一般內容（題目、故事步驟、名詞卡等）出現 `param.*`、`derived.*` 或 `amount` 就回報錯誤，並建議改用事件參照（例如把 `{{money:param.price}}` 改成 `{{money:e1.price}}`）。
   - 交易範本只有 `summary` 與 `explanation` 可以用 `param.*`、`derived.*`：`param.<name>` 必須是同一個範本 `params` 中的 `name`，`derived.<name>` 必須是同一個範本 `derived` 中的 `name`。範本的其他文字欄位（例如 `title`、參數的 `label`）只能用一般內容的寫法。
   - `amount` 只能出現在核心 `effects` 的片語樣板；片語樣板不可以用 `param.*`、`derived.*`。
3. **跨語言一致**：同一個欄位在各語系引用的佔位符集合（type、ref、選項）必須完全相同。這是「同一題兩種語言數值完全一致」的保證：數字只來自同一組參數，不來自譯者手打。
4. **formatToParts 往返**：對每個佔位符的值，以每個 complete 語系渲染成 parts，再把 minusSign、integer、decimal、fraction 組回數字，和「依宣告的位數四捨五入後的原值」比對；金額必須完全相等。日期則由 year、month、day 組回 ISO 字串比對。這可以抓到小數被吃掉、精度被捨入等問題。
5. **萬元 / million 規則**：見第 10.4 節。
6. **不得寫死金額或百分比**：佔位符以外的文字，若出現下列情況就回報錯誤：帶千分位的數字、4 位數以上的數字、緊鄰「元、萬、億、%、％、NT$、$、million、percent」的數字、全形數字。3 位數以下、沒有單位的整數（例如「第 3 步」「5 年」）允許。真的需要時用 `{{raw:...}}` 包住。
7. **介面字串**：同樣不寫死金額，金額一律當 ICU 參數傳入（第 3.2 節）。

```ts
// 往返檢查的核心（示意）
export function partsToNumber(parts: Intl.NumberFormatPart[]): number {
  let s = '';
  for (const p of parts) {
    if (p.type === 'minusSign') s += '-';
    else if (p.type === 'integer' || p.type === 'fraction') s += p.value;
    else if (p.type === 'decimal') s += '.';
    // group、currency、literal、percentSign、plusSign（|sign 的 +）不影響數值，略過
  }
  return Number(s);
}
```

百分比的 parts 組回來是「7.34」，比對時要用原值乘以 100 再依 digits 四捨五入。

## 11. 作答輸入的正規化

### 11.1 規則

| 步驟 | 處理 | 原因 |
| --- | --- | --- |
| 1 | `raw.normalize('NFKC')` | 注音輸入法全形模式會打出「１，０００．５」；NFKC 把全形數字、全形逗號、全形句點、全形減號（U+FF0D）、全形百分號、不換行空白都轉成半形 |
| 2 | 數學負號 U+2212 轉成 `-` | NFKC 不會轉換它；從計算機或文件複製的負數常帶這個符號 |
| 3 | 數字之間的「。」（U+3002）轉成 `.` | 全形模式可能打出句號當小數點 |
| 4 | 移除半形逗號、全形逗號與所有空白 | 千分位可有可無 |
| 5 | 依欄位單位移除允許的前後綴：金額欄的「元、NT$、$」，百分比欄的「%」，倍數欄的「倍、x、×」，以及開頭的「+」 | 學生常把單位一起打進去 |
| 6 | 檢查是否符合 `^-?\d+(\.\d+)?$` | 不符合就提示「請輸入數字，例如 -1,234.5」，提示不透露答案 |
| 7 | 括號形式的負數「(1,234)」不接受 | 提示「負數請用 - 號或 ± 按鈕」，避免和教材的「(-)」列名混淆 |

接受的三種負號：U+002D（一般減號）、U+2212（數學負號）、U+FF0D（全形減號）。

### 11.2 介面

- 輸入框用 `type="text"` 加 `inputmode="decimal"`，不用 `type="number"`（它拒絕逗號，各瀏覽器行為也不一致）；另設 `autocomplete="off"`、`autocorrect="off"`、`spellcheck="false"`、`enterkeyhint="done"`，字級至少 16px，避免 iOS 聚焦時放大。
- 輸入框旁固定提供「±」按鈕：iOS 的 decimal 鍵盤沒有負號。按下時切換開頭的負號，游標位置不變。
- 指標題的輸入框固定提供「N/A」按鈕：按下後答案狀態變成「分母不存在」，數字欄停用，再按一次取消（N/A 與 0 的差別見 04）。
- 按「確認答案」之前，在輸入框下方顯示「系統讀到：-1,234.5」（依介面語言格式化），讓學生在判分前發現打錯。
- 鍵盤開啟時，用 visualViewport 把輸入框捲到可見範圍（見 06）。

```ts
// packages/i18n/src/input.ts（示意）
export type NumericUnit = 'money' | 'percent' | 'times' | 'plain';

type NormalizeResult =
  | { ok: true; value: number }
  | { ok: false; reason: 'empty' | 'parentheses' | 'invalid' };

const UNIT_AFFIX: Partial<Record<NumericUnit, RegExp>> = {
  money: /^(NT\$|\$)|元$/g,
  percent: /%$/g,
  times: /(倍|x|×)$/gi,
};

export function normalizeNumericInput(raw: string, unit: NumericUnit): NormalizeResult {
  // 1 到 4：NFKC、數學負號、數字間的句號、逗號與空白
  let s = raw.normalize('NFKC').replace(/\u2212/g, '-').replace(/(\d)\u3002(\d)/g, '$1.$2');
  s = s.replace(/[,\uFF0C\s]/g, '');
  if (s === '') return { ok: false, reason: 'empty' };
  if (/^\(.*\)$/.test(s)) return { ok: false, reason: 'parentheses' };

  // 正負號可能在單位前（-NT$1234）或單位後（NT$-1234），所以單位前後各取一次
  let [sign, rest] = takeSign(s);
  const affix = UNIT_AFFIX[unit];
  if (affix) rest = rest.replace(affix, '');
  if (sign === '') [sign, rest] = takeSign(rest);

  if (!/^\d+(\.\d+)?$/.test(rest)) return { ok: false, reason: 'invalid' };
  const value = Number(sign + rest);
  return { ok: true, value: Object.is(value, -0) ? 0 : value };
}

/** 取出開頭的 - 或 +；+ 視為沒有符號 */
function takeSign(s: string): ['' | '-', string] {
  if (s.startsWith('-')) return ['-', s.slice(1)];
  if (s.startsWith('+')) return ['', s.slice(1)];
  return ['', s];
}
```

固定案例與預期結果（M2 寫成單元測試）：

| 輸入 | 欄位單位 | 預期結果 |
| --- | --- | --- |
| `１，０００．５`（全形） | plain | 1000.5 |
| `−1,234`（U+2212）、`－1,234`（U+FF0D）、`-NT$1,234`、`NT$-1,234` | money | -1234 |
| `1,234 元`、`$1,234` | money | 1234 |
| `７．３４％` | percent | 7.34 |
| `3.5倍`、`3.5x` | times | 3.5 |
| `12。5` | plain | 12.5 |
| `-0` | plain | 0 |
| `(1,234)` | money | 失敗，reason 為 parentheses |
| `--5`、`-+5`、`abc` | plain | 失敗，reason 為 invalid |
| 空字串或只有空白 | 任何 | 失敗，reason 為 empty |

另外用 fast-check：隨機整數與小數，用兩種語言的格式器輸出後再經過正規化，必須還原成同一個值；另外列舉全形、三種負號、混入空白與單位的固定案例。

- 設定「名詞卡同時顯示另一種語言」預設開啟，關閉後只顯示介面語言。
- 信心程度為「待確認」的譯名，在英文名稱旁顯示「譯名尚待確認」，不假裝確定。
- 名詞卡只有一個資料來源，闖關區與實驗室開的是同一張卡（見 03）。

### 13.2 名詞 chip

- 內文的 `{{term:tm_id}}` 渲染成 `<button>`，可讀名稱例如「存貨，開啟名詞卡」。
- chip 顯示的名稱依「這段文字的語系」，名詞卡本身依介面語言。
- `{{term:tm_id|plain}}` 只輸出文字，用在標題或已經有很多 chip 的句子。

## 14. 術語表的使用

- [12 術語表](12-glossary.md) 是撰寫時的參考來源（約 375 筆，底稿約 300 筆；欄位有教材用語、IFRS 英文、現行台灣用語與別名、旗標、信心程度、備註，類別依各節分組）。名詞資料由它整理而來：每一列核准後轉成一筆 Term（`tm_` 前綴，每筆有穩定 ID），欄位以 04 第 16.3 節為準。

| 12 的欄位 | 名詞資料（Term）的欄位 | 用途 |
| --- | --- | --- |
| 教材用語 | `teacherLabel`（教材原字）與 `label["zh-TW"]`（中文主要顯示；已決定 D13 採用 W01 到 W15，多數仍是教材原字，修正寫法時教材原字放進 `aliases`） | 中文主要顯示 |
| IFRS 英文 | `ifrsEnglish` 與 `label.en`（IFRS 沒有對應的列時 `ifrsEnglish` 為 null，描述性英文放 `label.en`） | 英文主要顯示、英文報表列名 |
| 現行台灣用語 | `currentTwLabel` | 名詞卡「現行用語」、搜尋 |
| 其他寫法 | `aliases`（`aliases["zh-TW"]`、`aliases.en`） | 搜尋 |
| 另一種英文拼法 | `enUsVariant`（美式拼字變體；已決定 D11 主要顯示用英式，美式只當搜尋別名） | 搜尋 |
| 類別 | `category`（04 的 enum：statement、account、ratio、concept、process、other） | 圖鑑篩選、分類題 |
| 旗標 | `flags`（04 的 TermFlag：japanese、old_name、typo_fixed、unused、not_ifrs_line、ifrs_treatment_differs、simplified） | 名詞卡旗標、報表的非 IFRS 項目標記（中英兩種介面） |
| 信心程度 | `confidence`（high、medium、pending），引用的 T 系列編號放 `pendingRefs[]` | 「譯名尚待確認」顯示、i18n 報表 |
| 備註 | `note` | 用語本身的說明，例如教材異寫的原因 |

- 圖鑑搜尋不分介面語言：同時比對中文、英文與別名；搜尋字串先做 NFKC 正規化並忽略大小寫。已決定（D13，W03）：介面統一用「應付帳款」「週轉率」，「應付賬款」「應付貨款」這類寫法收錄為搜尋別名；英文搜尋同時比對英式與美式拼法（`enUsVariant`）。
- 內文提到術語時用 `{{term:tm_id}}`，不直接打字；驗證器可以加一條警告（不是錯誤）：同一個欄位中，術語表裡的名稱以純文字出現、而且沒有用佔位符時提醒作者。
- 報表版面的每一列都引用名詞或科目 ID，英文列名從名詞資料取得，不在版面設定中另寫一份。

## 15. 新增第三種語言的檢查清單

以假設的日文（ja）為例：

1. 在 `packages/i18n` 加一筆設定，狀態先設 beta，決定退回鏈（例如 `['en', 'zh-TW']` 或 `['zh-TW']`，最後一定是 zh-TW）。登錄檔檢查要通過。
2. 語言切換元件自動從切換開關變成選單，確認選單在 320px 寬度下可用。
3. 執行 `lingui extract`，產生 `apps/web/src/locales/ja/messages.po` 與 `packages/web-ui/src/locales/ja/messages.po`，交給譯者；beta 期間缺字只進報表。
4. 內容的 LocalizedText 自動接受 `ja` 欄位（schema 由登錄檔產生）；用 i18n 報表追蹤進度。核心 `effects` 說明的文字範本與實驗室的 `aria-live` 播報句型也要補上新語言。
5. 名詞資料補上日文名稱與別名，標示信心程度。
6. 格式設定：`money`（後綴或 currency）、`compact` 級距（日文同樣有「万」與「億」，可比照 zh-TW）、`units` 的複數分類、`dateStyle`。驗證器的往返檢查與 compact 規則會自動套用到新的 complete 語系。
7. 輸入正規化：目前「移除逗號」的規則假設小數點是「.」。若新語言用逗號當小數點（例如德文），解析必須改成依該語系 `formatToParts` 取得的小數點與千分位符號，不能沿用現行規則。
8. 由右到左的語言（阿拉伯文、希伯來文）：設定 `dir: 'rtl'`；版面從一開始就用 CSS 邏輯屬性（`margin-inline-start` 等），Tab 順序與 ▲▼ 的意義要重新檢查。
9. 字型與字形：確認系統字型涵蓋該語言，`lang` 屬性正確，漢字字形才會依語言切換。
10. 長度：用最長的語言檢查 320px 寬度的 Tab 標籤、按鈕與表頭；Tab 標籤要有字數上限的說明。
11. 非 IFRS 項目標記（中文「非 IFRS 項目」、英文「Not an IFRS line item」，第 12.1 節）與名詞卡的 IFRS 處理段落，要有該語言的版本。
12. 網址（已決定 D5 的 C 案）：加入 `urlSegment`（例如 `ja`），路由會多一組 `/ja` 子路由；sitemap 的 hreflang 與用戶端寫入的 alternate 連結加上新語系；新語系的 catalog 與內容快照加進預先快取並重新計算預算；若當時已加入預先產生 HTML，預先產生清單也要加上新語系。
13. 隱私說明、關於頁、安裝教學（含截圖）翻譯完成。
14. 螢幕閱讀器（VoiceOver、TalkBack）以該語言語音實際聽過主要流程。
15. 介面缺字為 0、已發布內容缺字為 0、母語審稿者確認過術語之後，才把狀態改成 complete。

## 16. 測試

| 層級 | 內容 |
| --- | --- |
| 單元測試 | 各語系的金額、百分比、數值、日期格式化（en 為 en-GB，例如 3 November 2026）；負數、-0、極小負數；`\|sign` 變動值的正數、負數、0 與四捨五入後為 0 的值；compact 規則的邊界（999,999、1,000,000、2,485,000、100,000,000、152,340,000）；複數；登錄檔檢查（含 `urlSegment` 規則）；`matchLocale` 的比對順序；`localeFromPath`、`stripLocale`、`localePath` 的往返（`/`、`/en`、`/en/`、`/EN/level/...`、`/english/` 這類邊界） |
| 性質測試（fast-check） | 隨機金額經格式化、正規化後還原；佔位符渲染後的數字集合在兩種語言相同；隨機的語系無關路徑經 `localePath` 再 `stripLocale` 後不變 |
| 內容驗證 | 第 10.5 節的規則全部在 CI 執行；文件中的 JSON 範例也要通過 schema 驗證；`multi_choice` 的 `scoringMode` 與 `correctOptionIds`（至少兩個）檢查；sitemap 的每一筆中英網址互列 hreflang、x-default 指向中文、沒有列入 `noindex` 的頁面 |
| E2E（Playwright，Chromium、WebKit、Firefox） | 作答中切換語言後題目、選項、計時、捲動位置不變，網址在 `/level/<levelId>/` 與 `/en/level/<levelId>/` 之間以 replace 切換，按返回不會切回原語言；直接開啟 `/en/` 深層連結時第一次繪製前 `html lang` 為 en，Tab bar 已是英文標籤與 `/en/` 開頭的 `href`；已存偏好為 en 時根路徑 `/` 換成 `/en/`，沒有偏好時維持中文；英文瀏覽器開中文網址只出現一次切換提示；`multi_choice` 兩種 `scoringMode` 的提示在兩種語言都出現在 `<legend>` 中；教材版面的非 IFRS 項目標記在兩種語言都出現；IFRS 對照的表頭標示在兩種語言都出現；`html lang` 隨切換更新；退回的內容有「尚未翻譯」標記與 `lang="zh-TW"`；320px 寬度下兩種語言的截圖；以測試用的 beta 語系確認 beta 說明只出現一次 |
| 實機 | iOS 的 Intl 輸出與 `signDisplay`【待實測 V14】；VoiceOver 唸退回內容時是否切換成中文語音；VoiceOver 與 TalkBack 進入多正解題的選項群組時是否先唸出提示 |

## 建議新增的待確認

- 瀏覽器語言不是中文也不是英文時（例如日文、韓文），從中文網址進來是否也顯示「Prefer English? Switch」提示。D5 決定後語言由網址決定，這一點只影響提示，不影響預設語言；本文件暫定不顯示（`navigator.languages` 沒有比對到任何語系時不提示），但在台灣上課的外籍生可能比較希望看到英文的提示。
- 是否在內容欄位記錄「譯文對應的中文版本」（例如每個語系欄位附 `basedOnRev`），讓 i18n 報表能列出「中文已改、英文可能過期」的條目。這會增加 schema 欄位與作者的負擔，需要和 08 的改版規則一起決定。
- （已結案，2026-10-21）zh-TW 金額改顯示 NT$，不再有「元」後綴與空白的問題；只有 `|compact` 的「萬元 / 億元」維持中文寫法（第 10.4 節）。
