# 02 網站架構與頁面地圖

這份文件定義 LedgerLand 會計樂園有哪些頁面、每頁需要什麼資料、離線時的表現，以及手機、平板、電腦三種版面（加上寬螢幕）的導覽方式。它也規定課堂 QR 深連結怎麼組成、掃碼後的第一個畫面該長什麼樣，以及換頁、切換語言、在兩個模組之間往返時哪些狀態一定要保留。網址策略已決定（D5，2026-10-20）：中文頁面在根路徑，英文頁面在 `/en/` 底下，正式網域是 `ledgerland.swift.moe`（D4）；本文件的路徑表寫中文路徑，英文版一律在前面加 `/en/`，網址策略的比較紀錄在 [05 多語系](05-i18n.md) 第 7 節。

## 確定要做

- **頁面清單**：首頁、闖關地圖、章節、關卡（介紹、作答、結果）、錯題本、實驗室（首頁、故事、自由實驗、勾稽練習、指標實驗室）、名詞圖鑑與名詞頁、我的（進度、徽章、設定、備份）、安裝教學、隱私說明、關於與授權、找不到頁面，以及不出現在導覽中的 `/debug/` 量測頁。這些都是學習端的頁面；管理後台與瀏覽器匯入頁放在獨立的 origin（D10(d)、D10(e)），不在本文件的頁面地圖內，見 [08 題庫管理](08-content-admin.md)。
- **底部 Tab 五項**：首頁、闖關、實驗室、圖鑑、我的；英文為 Home、Quest、Lab、Terms、Me。圖示用 Phosphor（未選取用 regular、選取用 fill），文字標籤永遠顯示，Tab 上不放未讀紅點或數字。
- **已決定（D9，2026-10-20）：Tab 用短名，頁面標題與關於頁用模組全名**：闖關區／Quest、報表實驗室／Statement Lab、名詞圖鑑／Glossary。故事公司取原創名稱（情境與金額照老師的），由我在 M4 前提案、我確認；M8 前查詢「LedgerLand」與「會計樂園」是否與既有商標衝突。未採用的選項：中英都只用短名（英文短名太抽象，頁面標題說不清楚）；英文保留中文名或音譯（英文使用者與螢幕閱讀器都難以理解）。
- **四段版面**：compact（320 到 599px）、medium（600 到 1023px，直向與橫向不同）、expanded（1024px 以上）、wide（1440px 以上）。殼層（導覽列、整體欄位）依 viewport 斷點切換，元件（表格、題目卡、名詞卡）依 container queries 調整。最小支援寬度 320px。
- **導覽元件隨版面改變**：compact 用懸浮玻璃 Tab bar（往下捲動時收合、鍵盤開啟時隱藏）；medium 直向用置中的懸浮 Tab bar，medium 橫向改用側邊 rail；expanded 與 wide 用懸浮側邊欄。同一時間只會出現一種導覽元件，玻璃規格見 [07 設計系統](07-design-system.md)。
- **已決定（D8，2026-10-20）：正式支援 iOS 17**。初始 HTML 殼層 `index.html` 內含完整的 `<nav id="ll-tabbar">`（五個連結、圖示、中文標籤）；`<nav>` 之後有一段 inline「殼層在地化腳本」，在首次繪製前把英文頁（`/en/`）的標籤、`href` 與 `aria-label` 換成英文。React 不建立也不替換 `nav` 與其子元素，只更新 `aria-current`、標籤文字、`href` 與收合狀態，不使用 React portal；rail 與側邊欄是同一個 `nav`，由 CSS 依斷點改變外觀（第 2.2 節，標記見 07 第 6.1 節與 06 第 2.3 節）。這樣可以避開 iOS 17 以下「載入後才插入的元素不套用 backdrop-filter」的問題（Safari 18 才修正）；`-webkit-backdrop-filter` 由 Lightning CSS 或 Autoprefixer 依 browserslist 自動補上。測試尺寸矩陣加一台 iOS 17 裝置（第 3.7 節）。未採用的選項：能用但不正式支援（舊裝置一律走實色樣式）、不支援（擋掉還沒升級的學生）。
- **實驗室版面**：小手機一次只顯示一張表，用分段控制切換，恆等式摘要與四個勾稽燈號固定在上方；平板改成兩欄；電腦寬度足夠時三表並排。
- **其他已決定事項對實驗室頁面的影響**：科目變動階段以白話為主，「看分錄與 T 字帳」預設收合，「借貸與分錄」延伸章放在闖關地圖的延伸區（D1）；M4b 在故事步驟加完整公式樹與來源分錄的追蹤面板（D10(c)），並讓實驗室可以切換整套 IFRS 三表與指標，畫面標示「IFRS 對照，不計分」，闖關區一律用教材口徑計分（D10(f)）。版面安排見第 3.4 節。
- **測試尺寸矩陣**：320×568、375×667、393×852、430×932、手機橫向 852×393、iPad 直向 820×1180、iPad 橫向 1180×820、分割畫面 1/3 與 1/2、桌機 1440×900，以及每個斷點的邊界寬度；另加一台 iOS 17 裝置（D8）。
- **已決定（D5，2026-10-20）：網址採 C 案，中文在根路徑、英文在 `/en/`**。例如中文關卡是 `/level/lv_k7m2q9xd/`，英文是 `/en/level/lv_k7m2q9xd/`；中文首頁是 `/`，英文首頁是 `/en/`。先不預先產生 HTML：框架採 React Router 8 data mode 加 vite-plugin-pwa，所有頁面共用同一份殼層 `index.html`；主機 Cloudflare Workers 的 SPA fallback 對深層連結（包括 `/en/` 開頭的網址）回傳這份殼層並給 200，本案沒有語言選擇頁，fallback 絕不能回傳語言選擇頁（第 1.3 節）。作答狀態放在路由外的 store，切換語言時保留。日後若要加強搜尋收錄，再評估預先產生 HTML，網址不必改。未採用的選項見「需評估」第一項的決定紀錄。
- **深連結**：章節 `/chapter/<chapterId>/`、關卡（作答）`/level/<levelId>/`、故事步驟 `/lab/story/<storyId>/<stepId>/`，英文版在前面加 `/en/`；網址由穩定 ID 組成，ID 不重用；關卡不巢狀在章節底下，關卡換章節時 QR 連結仍然有效；關卡或章節下架時導向替代內容或章節頁。路徑字詞一律用英文小寫，不依語言翻譯；站內連結一律帶結尾斜線，日後若加入預先產生 HTML 也不必改連結。
- **課堂 QR 入口**：掃碼後直接進入關卡內容，不出現語言選擇，也不跳安裝提示；QR 的語言由網址決定（中文網址或 `/en/` 網址），可收合的提示橫幅（例如 App 內建瀏覽器提醒、語言切換提示）不能擋住內容。
- **已決定（D4，2026-10-20）：正式網域 `ledgerland.swift.moe`，主機 Cloudflare Workers Static Assets，base path 為 `/`**。`swift.moe` 的 DNS 在 Cloudflare；`_headers` 可以設定 CSP、`frame-ancestors` 與快取；深層連結以 SPA fallback 回 200；有 PR 預覽。已印出的 QR、學生的本機進度、已安裝的 App 都綁定 origin，所以給學生的 QR 一律用正式網域；M0a 的技術驗證可以先用暫時的 HTTPS 預覽網址，預覽網址上的資料一律視為測試資料，不印成 QR 發給全班。未採用的選項：學校子網域（DNS 變更要經過學校，主機選擇受限）、另購專用網域（每年費用，要另外管理）、`swiftruru.github.io`（origin 與其他 GitHub Pages 專案共用）。
- **Safari 分頁的常駐提示**：iOS 的 Safari 分頁顯示一條精簡的「已加入主畫面的同學，請從主畫面開啟」提示，附「匯出到 App」捷徑；在關卡頁上，提示同時寫出這一關的關卡代號，方便已安裝的學生在 App 裡輸入或改用 App 內掃描。可收合成小圖示，但不能永久關閉。QR 落地頁照樣直接顯示內容，只多這一條提示。流程與理由見 [06 PWA 與響應式](06-pwa-responsive.md) 第 4.7 節【待實測 V02、V03】。
- **已決定（D10(a)，2026-10-20）：已安裝 App 的學生有兩條不經過 Safari 的入口，M2 實作**。一是關卡代號：關卡介紹顯示關卡 ID 去掉 `lv_` 的 8 個字元，闖關地圖提供「輸入關卡代號」；二是 App 內相機掃描課堂 QR：內建 JS 解碼器並要求相機權限（Safari 沒有正式的 BarcodeDetector），解碼器選型在 M2 前查證。兩者的規則見第 4.7 節。同一項決定也包括 `persist()` 的時機（第 6 節）與匯出匯入的形式（備份檔加文字備份碼，匯入預設合併，見 06）。未採用的選項：不提供入口（學生要自己在 App 裡找關卡，有人會乾脆在 Safari 分頁作答，進度分成兩份）。
- **已決定（D10(b)，2026-10-20）：故事模式以連續故事為主線，每一步另有「單獨練習」入口**。單獨練習沿用故事在該步之前的狀態，網址是故事步驟路徑加 `?mode=practice`，不新增路由（第 5.4 節）。未採用的選項：獨立情境（失去故事感，累計概念難呈現）、兩者並存的完整版（路由與資料都要兩套，內容與測試量最大）。
- **跨頁面狀態保留**：返回時還原捲動位置；作答狀態（題目、已選選項、計時、捲動位置）放在路由外的 store 並寫入 IndexedDB，切換語言（換到另一種語言的同一頁網址）、開名詞卡、跳到實驗室再回來、App 進入背景、等待更新時都不會遺失。
- **巢狀頁面一律有 App 內的返回鈕**：主畫面 App 模式沒有瀏覽器的上一頁按鈕，不能只靠系統手勢。M3 起返回目的地固定（第 1.1 節的「返回目的地」欄、第 3.6 節）。
- **版面寬度**（M3，2026-10-25）：首頁、章節頁、名詞圖鑑、我的、徽章、安裝教學、關於系統設計是寬版（內容最寬 1040px），闖關地圖全幅，其他頁一般 720px；路由的 `handle.layout` 決定，Root 寫到 `<main data-layout>`（07 第 10 節）。
- **提示出現規則**：更新提示與安裝提示只出現在列表類頁面，不在作答中或實驗室步驟中出現（第 6 節）。
- **隱私說明頁與 debug 頁**：內容大綱見第 7、8 節。已決定（D7，2026-10-20）：從 M0b 起加入不用 cookie、不收集個資的流量統計，隱私說明頁與 debug 頁同步寫出統計的內容與狀態。

## 需評估

仍需評估的只有第二項（專注模式）。第一、三、四、五項已在 2026-10-20 決定，這裡保留精簡的決定紀錄，編號不變，方便其他文件引用；要做的事已寫進「確定要做」與內文。

### 一、路徑格式（網址策略）：已決定
- **已決定（D5，2026-10-20）**：C，中文在根路徑、英文在 `/en/`。先不預先產生 HTML，框架採 React Router 8 data mode 加 vite-plugin-pwa（原本 A 案的技術路線），V08 暫不需要；作答狀態放在路由外的 store，切換語言時保留。日後若要加強搜尋收錄，再評估預先產生 HTML。
- **未採用的選項**：A 不帶語系前綴（同一個網址無法用 hreflang 區分語言，分享者也無法指定語言）；B 全站 `/zh-TW/`、`/en/` 前綴（中文網址多 6 個字元，根路徑還要另外決定語言選擇頁或轉址，預先產生 HTML 的整合風險最高）。
- **對本文件的影響**：頁面總表改成「中文路徑加英文 `/en/` 前綴」與「收錄」欄（第 1.1 節）；不預先產生 HTML，收錄改靠 sitemap 的 hreflang（第 1.3 節）；QR 長度依正式網域重新計算（第 4.2 節）；落地頁的語言由網址決定（第 4.3 節）。

### 二、作答頁與實驗室步驟頁是否進入「專注模式」（隱藏 Tab bar）
- **選項 A：專注模式**。在 compact 與 medium 直向版面，關卡作答中與實驗室步驟播放中隱藏 Tab bar，改由頂部的「✕ 離開」與底部固定的主要按鈕（確認答案、繼續、下一步）操作。rail 與側邊欄版面不受影響。
  - 優點：底部只剩一個主要按鈕，拇指好按，不會誤觸 Tab；畫面高度多出約 70 到 90px，鍵盤開啟時也不會有兩層固定元素疊在一起；Safari 分頁模式下不會和浮動網址列擠在一起。
  - 缺點：想直接跳到別的 Tab 要先按「✕」；需要多設計一個頂部列。
- **選項 B：Tab bar 一直存在**，只在往下捲動時收合。
  - 優點：導覽一致，任何時候都能一鍵換區。
  - 缺點：主要按鈕得放在 Tab bar 上方，兩個固定元素同時佔用底部；小手機（320×568）上題目可視高度明顯變少。
- **建議**：選 A。離開時不跳確認對話框，因為作答狀態已經暫存，只顯示一則「已暫存，可隨時回來繼續」的提示。
- **由我決定**：registry 目前沒有對應編號，列在文末「建議新增的待確認」。

### 三、故事模式的形式影響實驗室路由：已決定
- **已決定（D10(b)，2026-10-20）**：C，連續故事為主線，每一步另有「單獨練習」入口，沿用故事在該步之前的狀態。路由依連續故事設計：故事步驟頁是 `/lab/story/<storyId>/<stepId>/`，單獨練習只在同一個路徑加非個人資料的模式參數 `?mode=practice`，不新增路由；`labRef` 寫成 `{ story, step }`，一律用步驟 ID（`st_` 加 6 碼），不用序號（見 [03 模組](03-modules.md) 與 [08 題庫管理](08-content-admin.md) 第 3.6 節）。
- **未採用的選項**：獨立情境 `/lab/case/<caseId>/`（每段短，但失去故事感，闖關題要改引用情境 ID）；兩者並存的完整版（路由與資料都要兩套，工作量最大）。日後若真的需要獨立情境，再加 `/lab/case/` 這一組，不改既有路徑。

### 四、Tab 與模組的正式中英名稱：已決定
- **已決定（D9，2026-10-20）**：Tab 用短名（首頁、闖關、實驗室、圖鑑、我的；Home、Quest、Lab、Terms、Me）；頁面標題與關於頁用模組全名：闖關區／Quest、報表實驗室／Statement Lab、名詞圖鑑／Glossary。故事公司取原創名稱（情境與金額照老師的），由我在 M4 前提案、我確認。M8 前查詢「LedgerLand」與「會計樂園」的商標。
- **未採用的選項**：中英都只用短名（英文短名較抽象，第一次看到的人不一定懂）；英文保留中文名或音譯（英文使用者與螢幕閱讀器都難以理解）。
- **對本文件的影響**：Tab 標籤在 320px 寬度下每格約 59px，短名符合中文 2 到 3 個字、英文 6 個字母以內的限制（第 2.1 節）；名稱要同步進 Lingui catalog 與安裝教學截圖（語系面細節見 05 需評估第三項的決定紀錄）。

### 五、已安裝 App 的學生掃到課堂 QR 時的入口：已決定
- **背景**：iPhone 相機掃 QR 很可能在 Safari 分頁開啟，而不是已安裝的主畫面 App【待實測 V03】；兩邊的儲存很可能不共享【待實測 V02】。
- **已決定（D10(a)，2026-10-20）**：關卡代號入口加 App 內相機掃描課堂 QR，兩者都在 M2 實作。關卡介紹顯示關卡代號（關卡 ID 去掉 `lv_` 前綴的 8 個字元），闖關地圖提供「輸入關卡代號」與「掃描課堂 QR」；掃描器內建 JS 解碼器並要求相機權限，解碼器選型在 M2 前查證。規則見第 4.7 節。
- **未採用的選項**：不做（學生要自己在 App 裡找關卡，章節多時費時，有人會乾脆在 Safari 分頁作答，進度分成兩份）；只做關卡代號、掃描留到 v2（決定時選擇兩者都做，讓學生不用打字，代價是解碼器的程式體積與相機權限）。

### 1.1 頁面總表

下表的路徑是中文版；英文版一律在前面加 `/en`（已決定 D5），例如名詞圖鑑是 `/en/terms/`、英文首頁是 `/en/`，路徑其餘部分完全相同。所有頁面都由同一份殼層 `index.html` 在瀏覽器端渲染，不預先產生 HTML（第 1.3 節）。「收錄」欄決定這一頁是否列入 sitemap（中英網址互列 hreflang），或在頁面上設 `noindex`。`<chapterId>`、`<levelId>` 等是穩定 ID，格式由 [08 題庫管理](08-content-admin.md) 第 4.1 節定義：章節 `ch_` 加 6 碼（例如 `ch_c5f8w2`）、關卡 `lv_` 加 8 碼（例如 `lv_k7m2q9xd`）、名詞 `tm_` 加 8 碼、故事 `story_` 加 6 碼（例如 `story_k8p3x6`）、故事步驟 `st_` 加 6 碼（例如 `st_r2x9k4`），隨機字串都是 Crockford Base32 小寫（不含 i、l、o、u）。

### 1.2 路徑規則（已決定 D5 的 C 案）

- 路徑字詞固定用英文小寫（`play`、`chapter`、`level`、`lab`、`terms`、`me`），不依語言翻譯。英文路徑就是在中文路徑前面加 `/en`；切換語言時只加上或移除這個片段，ID 與查詢字串都不變。語系片段的判斷與組合一律用 05 第 2.4 節的共用函式（`localeFromPath`、`stripLocale`、`localePath`，放在 `packages/i18n`），站內連結與 Tab 的目的地都由 `localePath()` 依目前語言產生，不在元件裡手寫 `/en`（Tab 的英文目的地在首次繪製前先由殼層在地化腳本寫好，第 2.2 節）。
- 三種深連結的格式固定為：章節 `/chapter/<chapterId>/`（例如 `/chapter/ch_c5f8w2/`，英文 `/en/chapter/ch_c5f8w2/`）、關卡（作答）`/level/<levelId>/`（例如 `/level/lv_k7m2q9xd/`，英文 `/en/level/lv_k7m2q9xd/`）、故事步驟 `/lab/story/<storyId>/<stepId>/`（例如 `/lab/story/story_k8p3x6/st_r2x9k4/`，英文 `/en/lab/story/story_k8p3x6/st_r2x9k4/`）。其他文件（例如 06 的效能量測網址）引用頁面時一律用這些格式。
- 路由用 React Router 8 data mode 的 `createBrowserRouter`：中文的子路由掛在 `/` 底下，英文的同一組子路由掛在 `/en` 底下，兩組由同一個函式依語系產生，頁面元件共用，不另寫一套。已決定（2026-10-20）：路由與頁面放在 `apps/web`；題目、回饋、名詞卡、報表表格等網站與後台共用的元件放在 `packages/web-ui`（見 [09 技術選擇](09-tech-stack.md) 第 8 節）。
- 根路徑 `/`：使用者主動選過英文（localStorage 的 `ll:locale` 為 en）時，head 裡的 boot 腳本在建立路由之前以 `history.replaceState` 把網址換成 `/en/`，不多一次請求，也不會先閃過中文；沒有偏好時（包括搜尋引擎爬蟲）就是中文首頁。只有根路徑這樣處理，其他網址一律照網址的語言顯示（05 第 8.3 節）。主畫面 App 的 `start_url` 是 `/`，所以選過英文的人從主畫面開啟時會直接進到英文首頁。
- 站內連結一律帶結尾斜線。沒有結尾斜線或大小寫不對的網址（例如 `/en`、`/EN/Level/LV_K7M2Q9XD`）由用戶端路由轉成小寫並補上斜線，再以 replace 導到正確網址；SPA fallback 對不存在的檔案直接回傳殼層，所以這一步由用戶端負責。猜測的 `/zh-tw/`、`/zh/` 開頭不是語系片段，以 replace 導到去掉這一段的中文網址。
- 日後若加入預先產生 HTML，結尾斜線也是必要條件：React Router v8 對結尾帶斜線的路徑產生 `<path>/_.data`（例如 `/en/_.data`）；沒有斜線時，client 導覽到 `/terms/abc` 會請求 `abc.data`，但建置只產生 `abc/_.data`（推論）。這一點與【待實測 V08】都只在那時才需要驗證，目前不需要。
- 查詢字串只放非個人資料的檢視狀態：`?term=`（開啟名詞卡）、`?from=`（從哪一題跳來；在 `/play/` 是剛完成的關卡 ID，播放移動動畫）、`?chapter=`（`/play/` 捲到該章）、`?via=qr` 或 `?via=code`（從課堂 QR 或關卡代號進入關卡，作答頁不顯示地圖的建議提示）、`?scan=1`（`/play/` 的掃描疊加層）、`?import=code` 或 `?import=file`（`/me/backup/` 直接打開匯入）、`?mode=practice`（故事步驟的單獨練習，第 5.4 節）、名詞圖鑑的搜尋與篩選。不放任何進度、語言或身分資訊（語言由路徑決定，不用 `?lang=`）。

來源：https://reactrouter.com/changelog 、https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/ 、https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/ （查證日期 2026-10-20）

### 1.3 不預先產生 HTML，以及收錄與分享預覽（已決定 D5）

- **殼層與 fallback**：建置輸出只有一份殼層 `index.html`，加上帶 hash 的 assets 與內容 JSON。Cloudflare Workers Static Assets 設 `not_found_handling = "single-page-application"`（設定檔是 `apps/web/wrangler.jsonc`），任何沒有對應檔案的導覽請求（例如 `/level/lv_k7m2q9xd/`、`/en/terms/tm_n7v3k8pq/`）都回傳這份殼層並給 200。殼層就是網站本身，不是語言選擇頁；本案沒有語言選擇頁，所以 fallback 不會、也不得回傳語言選擇頁。主機設定細節見 [09 技術選擇](09-tech-stack.md)。
- **離線**：Service Worker 由 vite-plugin-pwa 的 generateSW 產生，離線導覽的 fallback 是 `index.html`；precache 包含殼層、JS、CSS、兩種語言的 Lingui catalog 與內容快照，沒有逐頁 HTML 或 `.data`，所以名詞頁的數量不影響預先快取的體積。中文與英文網址離線時都能開啟，也能離線切換語言。快取策略見 06。
- **`html lang`**：殼層寫 `lang="zh-TW"`，boot 腳本在第一次繪製前依路徑改成正確值（`/en/` 開頭為 `en`），經由 SPA fallback 開啟的英文深層連結也一樣（05 第 9.1 節）。
- **收錄**：初始 HTML 只有殼層，搜尋引擎要執行 JavaScript 才看得到內容。hreflang 以建置時產生的 `sitemap.xml` 為主：上表「列入 sitemap」的頁面，中文與英文網址各一筆，互相列為 `xhtml:link` 的 alternate，x-default 指向中文網址（05 第 9.3 節）。頁面渲染後，用戶端也在 head 寫入 canonical 與 hreflang 的 `<link>`，但不依賴它。「不列入」的頁面不放進 sitemap，設 `noindex` 的頁面由用戶端在 head 加上 `<meta name="robots" content="noindex">`。**還沒做（既有缺口，2026-10-26 M3 回報時發現）**：建置時產生 `sitemap.xml` 這一步從 M0b 起都沒有實作，目前只有用戶端寫入的 canonical、hreflang 與 `noindex`；網站本身不受影響，只影響搜尋收錄。做法照本節（建置後依 content-manifest 列出「列入 sitemap」的頁面，中英網址互列）；排程由我決定，我建議在 M4a 開工時順手補上（只是建置後的一支腳本），最晚在 M8 公開上線前（14 第 5.2 節）。
- **分享預覽**：LINE 與社群網站產生預覽時通常不執行 JavaScript，所以所有頁面共用殼層裡同一組 og 標籤（站名與描述），中文與英文網址也相同。分享預覽暫時不顯示關卡或名詞的名稱。
- **日後**：若要加強搜尋收錄或讓分享預覽顯示頁面名稱，再評估預先產生 HTML（例如改用 React Router framework mode 的 prerender，或自寫只產生少數公開頁的小型腳本）。網址不必改，已印出的 QR 都還能用；屆時要驗證【待實測 V08】【待實測 V09】，並重新計算預先快取的預算。

### 2.2 行為規則

- 結構是 `<nav aria-label="主要導覽">`（英文介面為 "Main"）包住五個 `<a>`，目前頁面加 `aria-current="page"`，不使用 `role="tablist"`。
- 每個 Tab 的觸控範圍至少 44×44px，文字標籤永遠顯示。
- 再按一次目前所在的 Tab，依 iOS 原生 App 的習慣：若在子頁，回到該 Tab 的根頁面（例如從章節回到闖關地圖）；已在根頁面時，捲回頂端。作答中離開關卡不會遺失狀態（第 5 節），所以不跳確認對話框。
- Tab 上不放紅點或數字。到期的複習題改在首頁卡片顯示，維持「預設不給壓力」的語氣。
- 往下捲動時收合（只用 transform 與 opacity）、往上捲動時展開；減少動態效果時不收合或瞬間切換。虛擬鍵盤開啟時隱藏（以 visualViewport 偵測）。
- Tab bar 是 body 直屬的 fixed 元素，主內容使用整頁捲動，不放在 overflow 捲動容器裡。路由轉場動畫只套用在內容區，Tab bar 與它的祖先元素不設定 `view-transition-name`、opacity、filter 等會形成 Backdrop Root 的屬性。規格細節見 07。
- 因為正式支援 iOS 17（已決定 D8），Tab bar 不由 React 在載入後插入：殼層 `index.html` 內含完整的 `<nav id="ll-tabbar">`，是 `body` 直屬的元素，裡面有五個 `<a>`、Phosphor 的 regular 與 fill 兩套圖示與中文標籤，建置時由同一份設定產生。`<nav>` 之後有一段 inline「殼層在地化腳本」，英文網址（`/en/` 開頭）時在首次繪製前把標籤、`href`（`/en/`、`/en/play/` 等）與 `aria-label`（"Main"）換成英文。React 掛載後以 ref 取得 `#ll-tabbar`，只更新 `aria-current`、標籤文字、`href` 與收合狀態，切換語言時也只改文字與 `href`；React 不建立也不替換 `nav` 與其子元素，不使用 React portal。rail 與懸浮側邊欄是同一個 `nav`，由 CSS 依斷點改變排列與外觀，所以同一時間只會出現一種導覽元件。這段腳本和 head 的 boot 腳本一樣納入 CSP 的 sha256（見 09）。完整標記見 07 第 6.1 節，殼層見 06 第 2.3 節。

### 3.2 判斷方式

殼層依 viewport 的寬度與方向，元件依自己所在容器的寬度：

```css
/* 殼層：依 viewport 切換導覽元件 */
@media (width < 600px) { /* compact：懸浮 Tab bar */ }
@media (600px <= width < 1024px) and (orientation: portrait) { /* medium 直向：置中 Tab bar */ }
@media (600px <= width < 1024px) and (orientation: landscape) { /* medium 橫向：rail */ }
@media (width >= 1024px) { /* expanded：側邊欄 */ }
@media (width >= 1440px) { /* wide：內容置中，可停靠右側面板 */ }

/* 元件：依容器寬度，例如實驗室的表格區 */
.lab-tables { container: lab-tables / inline-size; }
@container lab-tables (width < 640px) { /* 一次一張表 */ }
@container lab-tables (640px <= width < 1000px) { /* 兩欄 */ }
@container lab-tables (width >= 1000px) { /* 三欄 */ }
```

需要在 JavaScript 裡依版面決定行為時（例如名詞卡要開成底部面板還是側邊面板），用同一組斷點的 `matchMedia` 包成 `useLayout()`，不另外寫一套數字。區間語法與 container queries 都在 Vite 8 預設建置目標（Safari 16.4、iOS 16.4 起）之內。已決定（D8，2026-10-20）正式支援 iOS 17，iOS 17 在這個建置目標之內，版面語法不需要另外的退路；要處理的是玻璃樣式（`-webkit-backdrop-filter` 自動補前綴、導覽元件寫在殼層，見第 2.2 節與 07）。

### 3.4 實驗室在各版面的排法

- **compact**：表格區一次只顯示一張表，分段控制有三段：損益表、現金流量表、資產負債表（與 03 第 3.12 節相同）。每一步有 10 個階段（見 03 第 3.3 節）；播放到第 5 到 7 階段時，分段控制會自動切到對應的表，使用者仍可手動切換；手動切換後，這一步內不再自動切換。第 9 階段的指標變化與第 10 階段的管理意涵是表格區下方的全寬面板，不佔分段。恆等式摘要（資產、負債、權益三個數字）與四個勾稽燈號用 sticky 固定在頂部列下方。「上一步、下一步」固定在底部。
- **medium**：兩欄。右欄固定是資產負債表（大部分變動最後都會流到這裡，勾稽 ③、④、⑤ 都會用到這張表），左欄用分段控制切換損益表與現金流量表；交易卡、預測、指標變化與管理意涵等階段說明放在兩欄上方（直向）或改成窄側欄（橫向且高度不足時）。03 第 3.12 節只列各版面的摘要並指向本節，平板與電腦的欄位分配以本節為準。
- **expanded 與 wide**：表格區寬度至少 1000px 時三表並排；側邊欄展開時若不夠寬，自動退回兩欄，使用者可以把側邊欄收合成 rail 換取寬度。
- **所有版面**：表格用真正的 `<table>` 與表頭；金額欄等寬數字、靠右對齊；窄欄時表格在自己的容器內水平捲動，整頁不出現水平捲軸。變動的列用醒目底色加 ▲▼ 與文字（例如「增加 120,000」），不只靠顏色。減少動態效果時不做位移動畫，直接標示結果（見 03 與 07）。
- **分錄層（已決定 D1）**：科目變動階段以白話說明為主，「看分錄與 T 字帳」是預設收合的展開區，在 compact 展開成全寬區塊，medium 以上展開在科目變動說明的下方，不另佔一欄。
- **IFRS 對照與追蹤（M4b，已決定 D10(c)、D10(f)）**：表格區上方有「教材／IFRS 對照」切換，切到 IFRS 時每張表的表頭都標示「IFRS 對照，不計分」（英文介面 "IFRS comparison, not scored"），勾稽練習與闖關區一律用教材口徑。點任何數字開啟「這個數字從哪裡來」面板（完整公式樹，最底層是來源步驟與可展開的分錄層）：compact 用底部面板，medium 以上用右側面板，和名詞卡共用同一個面板位置，一次只開一個。互動細節見 [03 模組](03-modules.md)。

### 3.6 頂部列與返回

- 第二層以下的頁面（章節、關卡、名詞頁、故事步驟、我的子頁）頂部一律有 App 內的返回鈕。主畫面 App 模式沒有瀏覽器的上一頁按鈕，不能假設學生會用手勢。
- 已改（2026-10-24，M3 全站設計系統）：返回鈕的目的地是固定的上一層，不是「回上一頁」，目的地與畫面上的短字見第 1.1 節總表的「返回目的地」欄（章節頁「地圖」回 `/play/?chapter=<id>`、作答頁回 `/play/?from=<levelId>`、名詞頁「圖鑑」回 `/terms/`、我的子頁「我的」回 `/me/`、診斷資訊「關於」回 `/about/`）。理由：從 QR、代號、分享連結或重新整理進來時沒有站內上一頁，固定目的地在每一種進入方式下都一樣，也不會把學生帶出網站；返回連結經 react-router，不整頁重新載入。原本的寫法：返回鈕「回上一頁」，直接開啟時改回上一層。
- 頂層五頁（首頁、闖關、實驗室、圖鑑、我的）用同一種頁首（07 第 9.2 節的 PageHeader；闖關頁是 HUD），切換 Tab 時頁首結構不跳。
- Android 的返回手勢與瀏覽器上一頁，會先關閉名詞卡、底部面板等疊加層，再回到上一頁。
- 換頁後焦點移到新頁面的 `h1`；從列表點進去再返回時，焦點回到剛才點的那張卡片（見 07 無障礙）。

## 4. 深連結與課堂 QR 入口

### 4.1 穩定 ID 的規則

- 章節、關卡、題目、名詞、故事、步驟各有隨機產生的穩定 ID，建立後不變、不重用，格式與改版規則（`rev`）見 08。
- 深連結只用 ID，不放章節序號或標題。關卡就算移到別的章節，網址也不變，所以關卡網址不包含章節 ID（是 `/level/<levelId>/`，不是 `/chapter/<chapterId>/<levelId>/`）。
- 實驗室的 `labRef` 寫成 `{ story, step }`，一律用步驟 ID（`st_` 加 6 碼），不用步驟序號；故事插入新步驟時，既有連結不受影響。

### 4.2 課堂 QR 的網址與長度

以正式網域 `ledgerland.swift.moe`（已決定 D4，20 個字元）與符合 08 格式的示意 ID 計算（關卡 `lv_k7m2q9xd`、章節 `ch_c5f8w2`、故事 `story_k8p3x6`、步驟 `st_r2x9k4`）。QR 用 byte 模式（小寫英文字母無法用 alphanumeric 模式），容量依 QR 規格（ISO/IEC 18004）：版本 3 為 29×29 模組，M 級 42 bytes、Q 級 32 bytes；版本 4 為 33×33 模組，M 級 62 bytes、Q 級 46 bytes；版本 5 為 37×37 模組，M 級 84 bytes、Q 級 60 bytes；版本 6 為 41×41 模組，M 級 106 bytes、Q 級 74 bytes。

| 用途 | 網址範例 | 字元數 | M 級 QR 版本 | Q 級 QR 版本 |
| --- | --- | --- | --- | --- |
| 關卡（中文） | `https://ledgerland.swift.moe/level/lv_k7m2q9xd/` | 47 | 4 | 5 |
| 關卡（英文） | `https://ledgerland.swift.moe/en/level/lv_k7m2q9xd/` | 50 | 4 | 5 |
| 章節（中文） | `https://ledgerland.swift.moe/chapter/ch_c5f8w2/` | 47 | 4 | 5 |
| 章節（英文） | `https://ledgerland.swift.moe/en/chapter/ch_c5f8w2/` | 50 | 4 | 5 |
| 故事步驟（中文） | `https://ledgerland.swift.moe/lab/story/story_k8p3x6/st_r2x9k4/` | 62 | 4（剛好放滿） | 6 |
| 故事步驟（英文） | `https://ledgerland.swift.moe/en/lab/story/story_k8p3x6/st_r2x9k4/` | 65 | 5 | 6 |

- 同樣的列印尺寸下，版本越小，每個模組越大，教室後排越容易掃到。列印時建議用 M 級：關卡與章節的中英網址都落在版本 4；故事步驟的網址比較長，課堂上優先投影關卡或章節的 QR。
- 英文網址只比中文多 3 個字元（`/en`），在 M 級下不改變關卡與章節 QR 的版本。
- QR 網址不加任何追蹤或其他參數；語言由路徑決定，不用查詢字串。課堂 QR 不連到單獨練習，`?mode=practice` 只用於站內連結（第 5.4 節）。
- 老師用的 QR 在站內產生（2026-10-26 我的決定，M3 收尾）：關卡介紹面板「給老師：關卡代號」展開列裡有「顯示 QR」，用掃描端同一套 `@zxing/library` 的編碼器（按下才動態載入）把這一關的正式網址（目前語言、帶 `?via=qr`）畫成黑白 SVG，可「下載圖片」（PNG）或「複製連結」；關於頁的「給老師」一節有說明。章節頁不另提供。

### 4.3 掃碼後的落地行為

1. 學生用相機（或 LINE 的掃描器）掃碼，網址在瀏覽器開啟。M0a 實測（2026-10-21）：iPhone 相機掃 QR 開在「相機的網頁面板」，儲存與 Safari、主畫面 App 分開，關閉就清空（06 決定五的實測補充）。已決定：偵測到暫存情境時頁面頂端顯示可關閉的提示卡「這個畫面關掉後，作答進度不會保留」，請學生點指南針改用 Safari，或在 App 裡用「掃描課堂 QR」；同時在給老師的使用說明寫明課堂上要先講這一步（下方第 8 點）。
2. 決定語言：依網址（已決定 D5）：`/en/` 開頭是英文，其餘是中文（見 05 第 8.3 節）。**不顯示語言選擇頁**，也不依偏好或瀏覽器語言自動轉址；網址的語言和瀏覽器語言或已存偏好不同時（例如英文瀏覽器掃到中文 QR），頂部顯示一次可關閉的切換提示，不擋內容。
3. 直接顯示關卡介紹狀態：關卡標題、目標、相關名詞、關卡代號、「開始」按鈕。第一個畫面要符合 06 的效能目標（mid-tier 節流下 LCP 不超過 2.5 秒）；流量統計的腳本不得延後這個畫面（第 7 節）。
4. **不顯示安裝提示**。安裝建議只在完成第一個關卡之後出現（第 6 節）。
5. 允許出現、但必須可收合且不擋住「開始」按鈕的提示：App 內建瀏覽器提醒（LINE、Facebook、Instagram）、iOS Safari 分頁的「已加入主畫面的同學，請從主畫面開啟」常駐提示（見「確定要做」與 06 第 4.7 節，提示中寫出這一關的關卡代號，並說明可以在 App 裡輸入代號或掃描 QR）、語言切換提示。
6. 若這台裝置有這個關卡未完成的作答暫存，介紹狀態多一個「繼續上次」按鈕，不自動跳進題目。
7. 若內容版本已更新而這個關卡的題目改版，暫存中受影響的題目作廢，並顯示「部分題目已更新」。
8. **給老師的課堂說明**（已決定 2026-10-21 的 C）：老師使用說明（M3 的安裝教學旁、關於頁連結）要寫一段「發 QR 時請提醒同學：用 iPhone 相機掃完後，先點右下角的指南針改用 Safari 開，進度才會保留；已經加入主畫面的同學，直接在 App 裡按『掃描課堂 QR』」。

### 4.4 ID 的解析結果

| 情況 | 判斷依據 | 行為 |
| --- | --- | --- |
| ID 存在且已發布 | content-manifest | 正常顯示 |
| ID 已下架，有替代關卡 | 發布快照的墓碑清單（`tombstones`，含 `supersededBy` 與所屬章節，見 08 第 4.5 節），由 ContentSource 的 `resolve(id)` 查詢 | 以 replace 方式導到替代關卡，顯示「這個關卡已改版，已帶你到新版」 |
| ID 已下架，沒有替代關卡 | 同上 | 導到原本所屬的章節頁，顯示「這個關卡已下架」 |
| 章節 ID 已下架 | 同上 | 導到闖關地圖，顯示說明 |
| 從未存在的 ID | manifest 查無資料 | 找不到頁面，提供闖關地圖與名詞搜尋 |
| 路徑大小寫錯誤 | 轉小寫後查得到 | 以 replace 方式導到正確網址 |

墓碑清單隨內容快照一起預先快取，所以離線時掃到舊 QR 也能正確導向。

### 4.5 iPhone 相機、LINE 掃描器與主畫面 App

- iPhone 相機掃 QR 會開在 Safari 分頁還是已安裝的主畫面 App，目前沒有官方資料，iOS 也不支援 manifest 的 `launch_handler`【待實測 V03】。規劃上假設會開在 Safari 分頁。
- Safari 分頁與主畫面 App 很可能各有一份儲存【待實測 V02】，所以落地頁多一條常駐提示，轉移方式見 06 第 4.7 節；已安裝的學生可以改在 App 裡輸入關卡代號或用 App 內掃描（已決定 D10(a)，第 4.7 節）。
- 台灣學生常用 LINE 內建的掃描器，網址會開在 LINE 的內建瀏覽器。在 iOS 上它是 LINE 自己的 WKWebView，能否註冊 Service Worker、儲存是否和 Safari 隔離、清除快取時是否刪掉 IndexedDB，都需要實測【待實測 V11】。偵測到內建瀏覽器時，顯示可收合的「改用 Safari 或 Chrome 開啟」橫幅，附複製連結按鈕，但不阻擋學習。
- 判斷目前是否為 App 模式一律用 06 定義的共用 `isAppMode()`，結果寫入 `html[data-display]`（值為 `app` 或 `browser`），各頁面不各自寫 display-mode 判斷【待實測 V01】。兩份事實核對對 iOS 主畫面 App 的 display-mode 看法相反：一份認為有 manifest 時 `display-mode: standalone` 為 true（依據 WebKit 原始碼與 bug 250651 的回報）；另一份引用 MDN BCD 的註記，認為 standalone 為 false、fullscreen 為 true（依據 WebKit bug 264218）。兩邊都還沒有定論，所以 `isAppMode()` 同時檢查 standalone、fullscreen 與 `navigator.standalone`，實際結果在 M0a 實機確認（見 06 第 2.7 節）。

來源：https://raw.githubusercontent.com/mdn/browser-compat-data/main/manifests/webapp/launch_handler.json 、https://bugs.webkit.org/show_bug.cgi?id=181849 （查證日期 2026-10-20）

### 4.6 給老師的使用建議（會放進關於頁或說明文件）

- QR 一律用正式網域 `ledgerland.swift.moe` 的網址（已決定 D4）。M0a 的暫時預覽網址只給內部測試，不印給學生，因為進度與安裝都綁定 origin。
- QR 指向關卡或章節網址，不要指向根路徑（根路徑是首頁，不是你指定的內容）。用中文上課時用中文網址，英語授課時用 `/en/` 開頭的網址；學生之後仍可在頁面上切換語言。
- 投影或列印前，用 iPhone 相機與 LINE 掃描器各掃一次確認。
- 已安裝 App 的同學不必經過 Safari：可以在 App 的闖關地圖輸入黑板上的關卡代號，或按「掃描課堂 QR」直接掃投影的 QR（第 4.7 節）。投影時把關卡代號寫在 QR 旁邊，兩種同學都方便。

### 4.7 關卡代號與 App 內掃描課堂 QR（已決定 D10(a)，M2 實作）

兩者都是給「已安裝主畫面 App、但老師投影的是 QR」的學生用的入口，入口都在闖關地圖頂部，以疊加層開啟（第 1.1 節補充）。

**關卡代號**

- 代號就是關卡 ID 去掉 `lv_` 前綴的 8 個字元（例如 `lv_k7m2q9xd` 的代號是 `k7m2q9xd`），不另外建立欄位，也不另外維護對照表。關卡介紹狀態顯示成 4 個字元一組（`k7m2 q9xd`），用等寬字型，320px 寬度下一行排得下。
- 輸入正規化依序是：NFKC（全形轉半形）、轉成小寫、移除空白與連字號、去掉開頭的 `lv_`（有輸入就接受），最後依 Crockford Base32 的慣例把容易混淆的 `o` 視為 `0`、`i` 與 `l` 視為 `1`（先去前綴再換字，`lv_` 的 `l` 才不會被換掉）。正規化後必須剛好是 8 個字元，而且都在 08 第 4.1 節的字元集之內（不含 i、l、o、u），否則提示「代號是 8 個英文字母或數字，請再核對一次」。
- 查詢：補回 `lv_` 前綴後，交給 ContentSource 的 `resolve(id)`，結果依第 4.4 節處理（已發布就進入、已下架就導到替代關卡或章節頁、查無資料就提示「找不到這個代號」）。content-manifest 與墓碑清單都在預先快取中，所以離線也能查。
- 導向的網址用目前的介面語言（`localePath()`），不因為輸入代號而改變語言。

**App 內掃描課堂 QR**

- 只在使用者按下「掃描課堂 QR」之後才呼叫 `getUserMedia`（後鏡頭），進入掃描畫面前先用一句話說明「需要使用相機來讀 QR，影像只在這台裝置上處理」。網站載入時與 QR 落地頁都不要求相機權限。
- 解碼用內建的 JS 解碼器（Safari 沒有正式的 BarcodeDetector），解碼器的套件選型在 M2 前查證（授權、體積、維護狀態、iOS 上的辨識速度）。解碼器與掃描畫面是動態載入的獨立 chunk，不計入首次載入的 JS 預算；它仍隨 app shell 預先快取，離線時也能掃描。
- 相機畫面只在裝置上解碼，不錄影、不截圖、不上傳。離開掃描畫面、讀到結果、或頁面進入背景（`visibilitychange` 轉為 hidden）時立即停止所有相機軌道。
- 讀到的內容只接受本站網址：origin 必須是 `https://ledgerland.swift.moe`（預覽環境則是目前的 origin），路徑必須符合章節、關卡或故事步驟三種格式（可以有或沒有 `/en` 前綴）；查詢字串一律忽略。符合時在 App 內以目前的介面語言導向（先 `stripLocale()` 再 `localePath()`），再經第 4.4 節的 ID 解析。不符合時顯示「這不是 LedgerLand 的課堂 QR」，絕不開啟其他網站的網址。
- 拒絕相機權限、沒有相機、或瀏覽器沒有 `getUserMedia` 時，掃描畫面改成關卡代號輸入框，並說明可以到系統設定開啟相機權限。
- 入口在 App 模式與一般瀏覽器都顯示（瀏覽器不支援 `getUserMedia` 時隱藏）；在 App 模式裡最有用，因為系統相機掃到的網址很可能開在 Safari 分頁【待實測 V03】。
- 學習端 `_headers` 的 `Permissions-Policy` 為 `camera=(self)`（見 [09 技術選擇](09-tech-stack.md) 第 11.2 節），App 內掃描因此可以使用相機；隱私說明頁要寫明相機的用途（第 7 節）。

### 5.2 作答工作階段的內容

作答工作階段至少包含：關卡 ID 與 `rev`、題目順序（題目 ID 陣列）、選項打散用的亂數種子、每題的已選選項 ID、數字題的原始輸入文字、是否已按「確認答案」與對錯、是否已展開解說、計時器（是否開啟、剩餘毫秒、是否暫停）、開始時間、捲動錨點。

- 選項順序由種子與選項 ID 決定，與文字無關，所以切換語言後順序不變。
- 每次作答變動都寫入 store；寫入 IndexedDB 以節流方式進行，另外在 `visibilitychange` 轉為 hidden 與 `pagehide` 時立即寫入。
- 套用 Service Worker 更新、或 IndexedDB 收到 `versionchange` 時，先寫入暫存再重新整理（見 06）。
- 作答狀態放在 store，不綁在路由參數上。已決定的 C 案（D5）中，切換語言等於換網址（以 replace 導到另一種語言的同一頁，查詢字串與 hash 保留），但 store 在路由樹之外，所以狀態不受影響。按返回不會把語言切回去。

### 5.3 跨模組前往

答錯交易題時按「看動畫」，會開啟 `/lab/story/<storyId>/<stepId>/?from=<questionId>`（英文介面是 `/en/lab/story/<storyId>/<stepId>/?from=<questionId>`），實驗室帶入交易前的狀態（流程見 03 第 4 節）。

- 離開作答畫面時計時器自動暫停，作答工作階段保留。
- 返回目標存在 store（只記最近一個來源），實驗室頂部顯示固定的返回膠囊「回到題目」；網址上的 `?from=` 只是重新整理或 App 被系統回收後的備援，只放題目或步驟 ID，不放進度資料（與 03 相同）。
- 按下「回到題目」後回到同一題、同一個捲動位置與回饋展開狀態，焦點回到「看動畫」按鈕。
- 在實驗室裡換到別的步驟，返回膠囊仍然保留，直到學生回去或關閉它。

### 5.4 故事步驟的開啟方式（已決定 D10(b)）

| 開啟方式 | 網址 | 帳本狀態 | 對進度的影響 | 這一步結束時 |
| --- | --- | --- | --- | --- |
| 故事模式（主線） | `/lab/story/<storyId>/<stepId>/` | 故事從第一步累計到前一步的狀態 | 完成後更新故事進度 | 「下一步」進入故事的下一步 |
| 單獨練習 | `/lab/story/<storyId>/<stepId>/?mode=practice` | 同樣沿用故事在這一步之前的狀態，不另外寫情境資料 | 不改變故事進度，只記錄這一步練習過 | 提供「再練一次」與「回到步驟列表」 |
| 從題目跳來 | `/lab/story/<storyId>/<stepId>/?from=<questionId>` | 交易前的狀態（與單獨練習相同） | 不改變故事進度 | 頂部固定「回到題目」膠囊（第 5.3 節） |

- 三種方式共用同一個路由與同一套元件，差別只在查詢字串，所以不新增路由，闖關題的 `labRef`（`{ story, step }`）也不受影響。
- 英文介面一律在前面加 `/en`，查詢字串不變。
- 故事步驟列表（`/lab/story/<storyId>/`）的每一步都有「開始」與「單獨練習」兩個入口；入口是否需要先完成前面的步驟，依 [03 模組](03-modules.md) 的解鎖規則。

```
  → (ID 已下架) 導到替代關卡或章節頁，並說明原因
```

## 建議新增的待確認

- 作答頁與實驗室步驟頁在 compact 與 medium 直向版面是否進入專注模式（隱藏 Tab bar）。我建議採用，理由見「需評估」第二項。
